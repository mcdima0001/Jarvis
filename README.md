# Jarvis

Голосовой ассистент для управления домашней студией: компьютер, ESP32, свет,
датчики, Telegram, YouTube, поиск.

Это **фундамент**, а не готовый продукт. Ядро собрано так, чтобы через год новая
возможность добавлялась одним файлом в `skills/`, а через несколько лет любую
часть (LLM, Whisper, TTS, память, шина, роутер) можно было заменить, не переписывая
остальное.

## Быстрый старт

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"

cp .env.example .env        # ключи и токены — только здесь
.venv/bin/python -m jarvis --check
```

`--check` собирает всю систему, печатает каталог инструментов и выходит.
Ни моделей, ни сети, ни API-ключа для этого не нужно.

### Режимы запуска

```bash
python -m jarvis                               # полный запуск
python -m jarvis --check                       # отчёт о сборке, без запуска
python -m jarvis --say "включи игровой режим"   # одна команда текстом
python -m jarvis --log-level DEBUG             # подробный лог
```

## Чтобы он слушал и отвечал

```bash
pip install -e ".[stt,voices,audio]"   # Whisper, все движки синтеза, звук
python -m jarvis --try-voice jarvis    # британские мужские, как в фильме
python -m jarvis --try-voice ru        # русские
python -m jarvis --devices             # посмотреть микрофоны
python -m jarvis                       # запуск
```

`--try-voice` скачивает голоса и произносит ими образец: выбираешь на слух,
понравившийся вписываешь в `tts.voices`. Модель Whisper скачается сама при
первом запуске (`small` — около 500 МБ).

### Голоса: пять движков

Голос пишется как `движок:голос`, свой на каждый язык:

| Движок | Где считает | Вес | Чем хорош |
|---|---|---|---|
| `edge` | облако | — | Нейроголоса Microsoft: естественнее всего локального |
| `kokoro` | локально | 338 МБ | Британские мужские голоса, быстро |
| `vosk` | локально | 750 МБ | Русский с интонацией по смыслу фразы |
| `silero` | локально | 39 МБ + torch | Русский, 48 кГц |
| `xtts` | локально | ~1.8 ГБ | Говорит любым голосом с образца |
| `piper` | локально | ~60 МБ | Самый лёгкий и быстрый |

```yaml
tts:
  voices:
    ru: vosk:male_1
    en: kokoro:bm_george
```

Это и стоит по умолчанию — сочетание, отобранное на слух из всех пяти движков.

Британские мужские у Kokoro — `bm_george`, `bm_daniel`, `bm_lewis`, `bm_fable`.
Послушать все четыре: `--try-voice jarvis`.

Русские: у Vosk интонацию расставляет отдельная модель BERT по смыслу фразы,
а не по одним знакам препинания — из локальных это самое живое звучание.
Пять дикторов лежат в одной модели, слушать так:

```bash
pip install -e ".[vosk]"
python -m jarvis --try-voice vosk
```

```yaml
voices:
  ru: vosk:male_0
```

Модель загружается один раз при старте и это не быстро (на слабом процессоре
до пары минут: разбирается словарь на 100 МБ). Дальше синтез идёт примерно
втрое быстрее реального времени.

### Если локальные голоса не устраивают

Локальный синтез упирается в потолок естественности. Облачные нейроголоса
Microsoft заметно живее — ключ и оплата не нужны, только интернет:

```bash
pip install -e ".[edge]"
python -m jarvis --try-voice cloud
```

```yaml
voices:
  ru: edge:ru-RU-DmitryNeural
  en: edge:en-GB-RyanNeural
```

Чем платим: около секунды на фразу против мгновенного Kokoro, зависимость от
сети и то, что реплики уходят на сторону Microsoft. Для команд студии это не
секреты, но знать стоит. Без интернета движок молчит — если это важно, держи
локальный голос запасным и переключай одной строкой.

### Один голос на обоих языках

Ни один движок не звучит одинаково хорошо на обоих языках, поэтому при
переходе на другой язык меняется и тембр. Это решается клонированием: XTTS
синтезирует речь по образцу, а образец снимается с уже выбранного голоса.

Прежде чем ввязываться, стоит понять, насколько это вообще нужно. Голос
выбирается **на всю реплику** по её языку, а латиница внутри русской фразы
читается русским голосом (см. `jarvis/core/tts/normalize.py`). То есть смены
голоса посреди предложения не бывает в принципе, и XTTS вступает только тогда,
когда реплика целиком на другом языке. Если второй язык у тебя редкий — проще
и лучше оставить на нём обычный движок.

**И только при наличии видеокарты.** На процессоре XTTS грузится минутами, а
синтез фразы идёт дольше самой фразы — для диалога непригодно, ассистент просто
замолкает на первой же реплике нужного языка. Учти и то, что клон звучит хуже,
чем исходный движок сам по себе: платишь качеством за единство тембра.

Направление выбираешь сам — клонируется тот голос, на котором говоришь чаще:

```bash
pip install -e ".[xtts]"
python -m jarvis --make-reference vosk:male_1        # снять образец
python -m jarvis --try-voice xtts:male_1             # послушать
```

```yaml
voices:
  ru: vosk:male_1        # основной — оригиналом, быстрее и чище
  en: xtts:male_1        # второй язык тем же тембром
```

Проверить, что видеокарта видна, можно до всякого синтеза:

```bash
python -c "import torch; print(torch.cuda.is_available())"
```

`False` — значит XTTS пойдёт на процессор, и включать его не стоит.

Эталон можно снять и с записи живого голоса — так клон получается чище всего,
без потери качества на промежуточном синтезе:

```bash
python -m jarvis --make-reference мой-голос.wav      # моно WAV, 10–20 секунд речи
```

Цена: модель ~1.8 ГБ и заметно медленнее остальных на процессоре. Держи
`tts.device: auto` — на видеокарте разница большая. Лицензия модели Coqui
разрешает некоммерческое использование.

Ставить всё не обязательно: `pip install -e ".[kokoro]"` или `".[silero]"`
по отдельности. Если движок не установлен, Jarvis скажет об этом в логе и
продолжит работать без синтеза.

Скажи **«Джарвис, какая температура»** — он ответит голосом. Можно позвать
просто «Джарвис», он скажет «Слушаю» и десять секунд будет ждать команду уже
без имени.

### Два языка

Понимает русский и английский, отвечает на языке вопроса:

```
— Джарвис, какая температура     → В студии 21.8 градуса.
— Jarvis, what's the temperature  → It's 22.3 degrees in the studio.
```

Как это устроено: язык определяется для каждой фразы, под него берётся свой
голос (русский голос английский текст внятно не прочтёт), а реплики скиллов
существуют в обоих вариантах.

Определение языка на коротких фразах ненадёжно — одиночное «Джарвис» Whisper
относит к английскому с уверенностью 0.27. Поэтому есть порог: ниже него
берётся основной язык из `stt.fallback_language`. Если хочешь определённости,
задай `stt.language: ru` или `en` жёстко.

Обращаться можно на любом языке: `audio.wake_word.phrases` содержит и
«джарвис», и «jarvis».

### Настройка под своё железо

Всё в `config/config.yaml`, менять по одной строке:

| Что | Где | Смысл |
|---|---|---|
| Точность распознавания | `stt.model` | `tiny` → `base` → `small` → `medium`. На GTX смело `medium` |
| Видеокарта | `stt.device` | `auto` сам найдёт CUDA и включит float16; `cpu` — принудительно |
| Микрофон | `audio.input_device` | номер или часть имени из `--devices` |
| Чувствительность | `audio.vad.threshold` | `0` — замерить фон комнаты самому; иначе 0.01–0.05 |
| Пауза до конца фразы | `audio.silence_ms` | больше — успеваешь подумать, меньше — быстрее отклик |
| Имя | `audio.wake_word.phrases` | и `mode: none`, если не нужно звать по имени |
| Голоса | `tts.voices` | по голосу на язык; выбрать на слух — `--try-voice` |
| Скорость речи | `tts.length_scale` | `<1` быстрее, `>1` медленнее |
| Язык | `stt.language` | `auto` или жёстко `ru` / `en` |

### Если не реагирует

Запусти с `--log-level DEBUG` — в логе видно строку `Распознано: ...` с тем,
что услышал Whisper. Дальше по ситуации:

* **Имя слышится неправильно** («жаркость» вместо «Джарвис») — допиши
  услышанное в `audio.wake_word.aliases`. В логе такие случаи помечаются как
  «Похоже на обращение, но не уверен».
* **Ничего не распознаётся** — проверь микрофон в `--devices` и порог
  `audio.vad.threshold`.
* **Команду слышит, но не выполняет** — распознавание неточное («включи» →
  «в куче»). Это лечится ключом OpenRouter: тогда непонятые фразы разбирает
  языковая модель, а не только точные совпадения.

### Свободный диалог

Ключ OpenRouter — в `.env`, переменная `JARVIS_OPENROUTER_KEY`. Без него
команды по фразам работают, а разговор и разбор неточных формулировок — нет.

## Структура

```
jarvis/core/       ядро: конфиг, шина, инструменты, роутер, скиллы, LLM, память, аудио
skills/            плагины — всё, что Jarvis умеет (см. skills/README.md)
config/config.yaml все настройки; в коде нет ни путей, ни ключей
memory/            память: documents/*.json и journals/*.jsonl
models/, logs/     модели и логи (в .gitignore)
tests/             тесты на швы архитектуры
```

## Как это устроено

Полный разбор решений и обоснования — в [ARCHITECTURE.md](ARCHITECTURE.md).
Коротко:

* **Два канала связи.** Факты идут в шину событий (`sensor.temperature.changed`),
  команды — через реестр инструментов (`await tools.invoke("esp32.get_temperature")`).
  Скиллы никогда не импортируют друг друга.
* **Роутер отдаёт намерение, а не скилл.** Цепочка резолверов: точные фразы →
  синонимы → LLM → диалог. Типовые команды студии до сети не доходят.
* **Провайдер LLM тонкий.** `complete()` и всё. Задачи (`ask`, `summarize`,
  `extract_intent`) написаны один раз в `LLMService`, поэтому новый провайдер —
  это один метод.
* **Скилл = файл в `skills/`.** Инструменты, фразы и JSON Schema выводятся из
  сигнатур и докстрингов. Регистрировать вручную ничего не нужно.

## Добавить возможность

Создай `skills/имя/skill.py`:

```python
from jarvis.core.contracts import ToolResult
from jarvis.core.skills import Skill, SkillMeta
from jarvis.core.tools import tool


class TimerSkill(Skill):
    meta = SkillMeta(name="timer", description="Таймеры")

    @tool(phrases=["поставь таймер на {minutes} минут"])
    async def start_timer(self, minutes: int) -> ToolResult:
        """Запустить таймер.

        :param minutes: длительность в минутах.
        """
        return ToolResult.success(minutes, speech=f"Таймер на {minutes} минут.")
```

Перезапусти — команда работает. Ядро и конфиг не трогаются.
Подробнее: [skills/README.md](skills/README.md).

## Тесты

```bash
.venv/bin/python -m pytest
```

Тесты покрывают именно швы: доставку и изоляцию событий, вывод схем и вызов
инструментов, порядок резолверов (в том числе что известная фраза **не** доходит
до LLM), загрузку и выгрузку скиллов, подстановку переменных в конфиге.

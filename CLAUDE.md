# CLAUDE.md — контекст проекта Jarvis

Файл для восстановления контекста, если сессия потеряна. Читается автоматически
при старте. Держать в актуальном состоянии обязательно.

## О проекте

Голосовой ассистент для управления домашней студией: компьютер, ESP32, свет,
датчики, Telegram, YouTube, поиск. Репозиторий `mcdima0001/Jarvis` (приватный),
рабочая копия `/root/Jarvis`.

**Это фундамент, а не готовый продукт.** Приоритеты владельца, по важности:
архитектура → чистый код → простота расширения. Функциональности намеренно
немного; ценность в том, что новая возможность добавляется файлом в `skills/`,
а любая часть системы заменяется без переписывания остального.

## Общение и рабочие правила

- К пользователю обращаться **на «ты»**, по-русски.
- Идентификаторы в коде английские, докстринги и документация — русские.
- **Заканчивая работу — коммитить и пушить** в `main` без напоминаний.
- **CLAUDE.md обновлять** при значимых изменениях архитектуры или состояния.

**Моделей на сервере не поднимать** (просьба владельца от 29.07.2026): два
слабых ядра, Whisper с Vosk грузятся две минуты. Поэтому `--check` теперь
стартует систему без звука, распознавания и синтеза (`start(models=False)` →
`ServiceRunner.start_all(skip_heavy=True)`) — конфиг, скиллы и каталог
инструментов он проверяет и так. Полный запуск и `--say` — только у владельца;
что нужно проверить, отдавать ему списком.

```bash
# это выполняет владелец у себя, не мы
python -m jarvis                                       # живой запуск с микрофоном
python -m jarvis --say "какая температура"             # одна команда, ответ голосом
python -m jarvis --say "включи трек X" --no-voice      # то же, но молча и мгновенно
```

**Уши и голос поднимаются по отдельности** (`needs=EARS|VOICE` у сервисов,

получает команду текстом, и Whisper ему не нужен — а грузился вместе с

текста (доступ настроен 30.07.2026, `ssh laptop` через Tailscale):

## Архитектура: решения, которые нельзя откатывать не подумав

Полные обоснования — в `ARCHITECTURE.md`. Здесь суть, чтобы не переделать по кругу.

1. **Два канала связи.** События (`EventBus`) — факты, 1→N, без ответа.
   Команды (`ToolRegistry`) — 1→1, через `await`, с `ToolResult`. Чистый pub/sub
   на запросах вида «какая температура» выродился бы в correlation-id и таймауты
   в каждом скилле. **Скилл никогда не импортирует скилл** — только
   `await self.tools.invoke("имя.инструмента", {...})`.
2. **Роутер отдаёт `Intent` (имя инструмента + аргументы), а не скилл.** Поэтому
   правила и function-calling LLM взаимозаменяемы. Цепочка резолверов:
   `phrase → alias → learned → llm → fallback`. Типовые команды студии до сети не доходят —
   это главная экономия.
3. **`LLMProvider` тонкий: только `complete()`.** Задачи `ask/chat/summarize/
   extract_intent` живут в `LLMService` и написаны один раз. Новый провайдер
   (Gemini, Groq, DeepSeek) = один метод. Профили задач в конфиге дают разные
   модели под разные задачи и смену модели в рантайме (`llm.set_model`).
4. **Whisper и Piper синхронные** — ходят только через `BlockingWorker`. Вызов
   в корутине заморозил бы весь event loop; `async def` сам по себе не спасает.
5. **VAD и wake word** — протоколы с пропускающими заглушками. Без них Whisper
   молотит на любом шуме студии.
6. **Память: два хранилища.** `DocumentStore` (JSON, read-modify-write) для
   `profile/preferences/studio/projects/knowledge`; `JournalStore` (JSONL,
   append-only) для `today/history`. У `ContextBuilder` **нет метода «дай всё»** —
   разделы называются явно, результат режется по бюджету токенов.
7. **`core/contracts/`** — слой, от которого зависят все и который не зависит ни
   от кого. Шов для замены шины, роутера, памяти.
8. **`SkillScope`** — все регистрации скилла (инструменты, подписки, задачи) идут
   через него, выгрузка = `revoke()`. Это же делает возможным `reload`.
   **Подскиллы** (с 30.07.2026): скилл, который не работает без другого, лежит
   внутри него — `skills/browser/page/skill.py`. Это не про красоту каталога:
   `page` зовёт `browser.page_run` и соседом по списку выглядел как вторая
   независимая возможность «для браузера». Вложенность даёт порядок загрузки,
   зависимость (нет главного — подскилл не пробуем) и выгрузку вместе.
   Уровень вложенности **ровно один**. **Имена инструментов от вложенности не
   зависят** — берутся из `meta.name`, `page.pause` остаётся `page.pause`: на
   такие имена ссылается выученное в памяти, а `browser.page.pause` рядом с
   существующим `browser.page_run` читалось бы как одно и то же.
9. **Секреты через `${VAR}` из `.env`**, в коде нет ни путей, ни ключей.
10. **DI через конструкторы**, composition root — `jarvis/core/app.py`. Ни
    глобальных переменных, ни синглтонов.

## Грабли, на которые уже наступали

- **Кеш байткода ломает reload.** Заголовок `.pyc` хранит mtime с точностью до
  секунды: файл, переписанный в ту же секунду без изменения размера, считается
  неизменным, и перезагрузка поднимает старый код. Поэтому `skills/loader.py`
  читает и компилирует исходник вручную, не через `spec.loader.exec_module`.
- **Порог уверенности не применяется к последнему резолверу.** Иначе `fallback`
  с его низкой уверенностью отсекался бы и свободный диалог был бы недостижим.
- **Шаблоны фраз проверяются от частного к общему.** «Найди в гугле котиков»
  подходит и под `найди {query}` (скилл search), и под `найди в {engine}
  {query}` (скилл browser). Раньше побеждал тот, чей скилл загрузился раньше,
  то есть алфавит имён файлов. Теперь шаблоны сортируются по числу собственных
  букв (`_specificity` в `resolvers/phrase.py`), и правило понятно без чтения
  кода: чем больше в шаблоне своих слов, тем он главнее.
- **Шаблоны фраз матчатся по тексту в исходном регистре** (`Utterance.cleaned`),
  иначе аргумент вида «кабель XLR» сохранялся бы как «xlr».
- **`re.escape` съедает фигурные скобки** — шаблон `включи {mode} режим` нужно
  собирать по кускам, а не экранировать целиком.
- **Шаблон `.gitignore` без ведущего слэша бьёт по любой глубине.** Правило
  `memory/` вырезало из репозитория не только рантайм-каталог в корне, но и
  `jarvis/core/memory/` со `skills/memory/` — на сервере всё работало, а на
  чистом клоне запуск падал с `ModuleNotFoundError`. Каталоги данных писать
  только как `/logs/`, `/models/`, `/memory/`.
- **Проверять репозиторий чистым клоном, а не рабочей копией.** Локально
  проходящие тесты ничего не говорят о том, что реально попало в git:

  ```bash
  git clone git@github.com:mcdima0001/Jarvis.git /tmp/clone-test
  cd /tmp/clone-test && python -m jarvis --check && python -m pytest -q
  ```

## Голос: как это настроено

```bash
pip install -e ".[stt,audio,voices]"
python -m jarvis --download-voice          # список голосов
python -m jarvis --try-voice ru            # послушать и выбрать
python -m jarvis --devices                 # номера микрофонов и колонок
```

- **Два языка: русский и английский.** Понимает оба, отвечает на языке вопроса.
  Язык определяется для каждой фразы, под него берётся свой голос, реплики
  скиллов существуют в обоих вариантах (`speech={"ru": ..., "en": ...}`).
- **STT**: faster-whisper, модель `small`, `device: auto` (сам находит CUDA:
  float16 на видеокарте, int8 на процессоре, с откатом на CPU при сбое).
  `language: auto` со списком `languages`, порогом `language_min_probability`
  и откатом на `fallback_language`.
- **Edge**: облачные нейроголоса Microsoft (`edge:ru-RU-DmitryNeural`). Единственный
  движок, считающий не локально. Ключа не требует; цена — ~1 с на фразу,
  зависимость от сети и уход реплик наружу.
  Синтез проверен на сервере: MP3 декодируется через PyAV, распознаётся верно.
  Владельцу русские голоса Edge тоже не подошли, и задержка ощутима.
- **Vosk**: последняя ставка на русский. Интонацию расставляет отдельная модель
  BERT по смыслу фразы, а не по знакам препинания — отсюда живость, которой не
  хватало остальным локальным. Модель `vosk-model-tts-ru-0.9-multi` (750 МБ,
  Apache 2.0), пять дикторов в одном файле: `vosk:male_0`, `vosk:male_1`,
  `vosk:female_0…2`. На сервере проверены скачивание, распаковка, загрузка
  модели и разбор `speaker_id_map`; **синтез не прогонялся** — слушает владелец.
  Учесть: загрузка модели заняла 2 минуты на двух ядрах (парсится словарь на
  100 МБ). Она однократная — `CompositeTTS.start()` греет голос при запуске.
- **XTTS**: клонирование голоса, нужен ради вставок на втором языке тем же
  тембром. Основной язык русский, поэтому направление обратное первоначальному:
  эталон снимается с выбранного русского голоса, а XTTS договаривает английские
  куски. Образец: `--make-reference vosk:male_0` либо `--make-reference файл.wav`
  (запись живого голоса — так чище всего, без промежуточного синтеза), кладётся
  в `models/xtts/<имя>.wav`; дальше `en: xtts:male_0`. Текст эталона берётся на
  родном языке голоса — иначе движок читает чужой алфавит по буквам.
  **Синтез XTTS на сервере не прогонялся.**
  Тонкость установки: `coqui-tts` требует `transformers>=4.57`, но ломается на
  ветке 5.x (оттуда убрали `isin_mps_friendly`), поэтому в extra зафиксировано
  `<5.0`. Ещё нужны `torchaudio` и `torchcodec`.
- **TTS**: движки за одним интерфейсом (`jarvis/core/tts/backends.py`),
  выбор на каждый язык записью `движок:голос` в `tts.voices`:
  `kokoro` (24 кГц, британские мужские голоса, модель 338 МБ),
  `vosk` (22 кГц, русский с просодией по BERT, модель 750 МБ),
  `silero` (48 кГц, русский, нужен torch),
  `piper` (22 кГц, самый лёгкий). Диспетчеризация — в `CompositeTTS`,
  загрузка ленивая и кешируется. Частоту задаёт сам голос, конфиг тут не указ.
  Скорость задаётся одной настройкой `length_scale` (больше — медленнее), и
  каждый движок пересчитывает её под себя: у Kokoro и Vosk это обратный темп,
  у Edge — проценты.
  Выбрать на слух: `python -m jarvis --try-voice jarvis|ru|en|vosk`.
- **VAD**: энергетический, чистый stdlib. `threshold: 0` включает калибровку по
  фону комнаты за первую секунду.
- **Активация по имени — по тексту, а не по звуку.** Распознавание локальное и
  бесплатное, поэтому дешевле расшифровать фразу и посмотреть, начата ли она с
  имени, чем держать отдельную модель wake word. Сравнение нечёткое плюс список
  `aliases`.
- После голого «Джарвис» открывается окно `follow_up_s` (10 с), в котором
  команда принимается без имени.

## Манера речи

`jarvis/core/persona.py` — единственное место, где решается, как ассистент
звучит. Пять ситуаций: `listening` (позвали по имени), `done`, `failed`,
`greeting`, `farewell`. У каждой набор вариантов на русском и английском;
подряд один и тот же не повторяется (помним половину набора). Владелец просил
манеру из фильма — отсюда обращение «сэр» и сдержанный тон.

- **Свои слова команды тоже варьируются, и выбирает их персона** (`choose`,
  добавлено 30.07.2026 по просьбе владельца «разнообразь ответы»). `ToolResult.speech`
  принимает набор: `{"ru": ("Пауза.", "Остановил."), "en": (...)}`. Разделение
  тут не формальное: **что** сказать знает скилл, а «не повторяться» и «помнить,
  что уже сказал» — одна забота на всю систему, иначе в каждом скилле завелась
  бы своя копия дедупликатора. Память своя на каждый ключ (обычно имя
  инструмента): сказанная «пауза» не должна вытеснять «включаю».
  `speech_options()` разбирает четыре вида реплики (строка, набор, словарь по
  языкам, словарь наборов), а `speech_for()` возвращает **первый** вариант — для
  текстового ввода, `--say` и тестов, где персоны под рукой нет и нужна
  предсказуемость. Выбор живёт в `VoicePipeline`, потому что персона есть только
  там.

- **Обращение — поле `{address}`, а не текст фразы.** Меняется одной строкой
  `persona.address` в конфиге, в том числе на пустую: тогда из шаблона
  убирается и обращение, и запятая при нём, иначе вышло бы «Слушаю, .».
- **Тот же характер уходит в системную подсказку `core.chat`** (`Persona.style`),
  иначе ассистент отзывается как Джарвис, а разговаривает как чат-бот.
  Это ~40 токенов и только в задаче `dialog` — каталог инструментов дороже
  на два порядка.
- **Приветствие и прощание живут в `JarvisApp.run`, а не в `pipeline.start`.**
  Это свойство живого сеанса: при подъёме сервисов `--check` и одиночная
  команда `--say` тоже здоровались бы и прощались.
- **Фразы обязаны укладываться в алфавит движка** — тест
  `test_phrases_survive_speech_normalization` прогоняет каждую через
  `normalize_for_speech`. Для русских наборов латиница запрещена: голос
  прочитает её кашей.
- **Опечатка в названии ситуации ловится предупреждением** при сборке персоны.
  Молча проигнорированный набор из конфига — это ровно те грабли, что уже были
  с `router.aliases`.
- Своё объяснение ошибки важнее вежливого отказа: `_describe` берёт
  `result.error`, если он есть, и только иначе — реплику персоны.

## Голос: грабли

- **Whisper не знает слова «Джарвис»** — слышит «жаркость», «жар виск», «Зарез».
  Лечится `stt.initial_prompt`: подсказка словаря даёт уверенное распознавание
  имени. Проверено — без неё гейт по имени отсекает почти всё.
  `hotwords` не подходит: местами выкидывает имя целиком.
  **То же и с названиями сайтов.** «GitHub» приходил как «Geed Hub», «Geat Hub»
  и «гитхап» — три разных написания за минуту. Нечёткое сравнение такое не
  вытягивает («geedhub» похоже на «github» на 0.62) и не должно: порог, при
  котором это ловится, начнёт открывать сайты на любое слово. Чинить нужно на
  слое распознавания — дописать название в `stt.initial_prompt`.
- **Имя нужно вырезать всегда, а не только при гейте.** Иначе в окне ответа и
  при вводе текстом роутер получал «Джарвис, включи свет» и не находил команду.
  Разбор вынесен в `_strip_wake`, гейт — в `_extract_command`.
- **Автоопределение языка врёт на коротких фразах.** Одиночное «Джарвис»
  Whisper относит к английскому с уверенностью 0.27 и слышит «I miss»;
  «включи свет» даёт ru всего 0.58. Поэтому определение принимается только
  выше порога и только для разрешённых языков, иначе берётся основной.
  Используется отдельный дешёвый проход `model.detect_language`, а не второе
  полное распознавание.
- **Нечёткое сравнение не работает между алфавитами.** Похожесть «jarvis» и
  «джарвис» близка к нулю, поэтому имя хранится списком написаний
  (`wake_word.phrases`) и сравнивается с каждым.
- **Латиница в реплике превращается в кашу.** Piper гонит текст через espeak-ng
  с русскими правилами: «Ключ OpenRouter в файл .env» звучит так, что
  распознаётся обратно как «ключ об англутов в файл n». Чистая русская фраза
  произносится нормально — проверено сравнением синтеза и распознавания.
  Лечится в `jarvis/core/tts/normalize.py`: перед синтезом латиница переводится
  в русское чтение (словарь известных названий плюс транслитерация остального).
  Нормализация живёт в слое TTS, а не в скиллах, потому что латиница попадает в
  речь ещё и подстановками — именами скиллов, `steam.exe`, `anthropic/claude-…`.
  Свои названия добавляются в `tts.pronounce`.
  Правило для авторов скиллов: в `speech` — живая русская фраза, технические
  подробности в `error`/`value`.
- **`asyncio.run` падает, если петля уже крутится.** Интерфейс движков синтеза
  синхронный, а облачный клиент внутри асинхронный. В потоке `BlockingWorker`
  своей петли нет и `asyncio.run` работает, но служебные команды CLI дёргают
  движок прямо из корутины — там всё рушится. Поэтому есть `_run_blocking`
  (уводит работу в поток, если петля активна), а служебные режимы вынесены
  в `_run_utility` и выполняются **до** `asyncio.run`.
  Проверять такие вещи на сервере скриптом бесполезно: в скрипте петли нет,
  и баг не воспроизводится — нужен запуск через реальный CLI.
- **`ToolResult.speech` бывает картой языков.** Везде, где реплика выводится
  или произносится, нужен `speech_for(язык)`, иначе наружу уезжает сырой
  словарь. Один раз уже уехало в вывод `--say`.
- **У текстового ввода язык никто не сообщает.** Для голоса его даёт Whisper,
  для `--say` и Telegram — `detect_language` по алфавиту.
- **Ассистент слышит сам себя.** Колонки произносят ответ, микрофон его ловит,
  Whisper расшифровывает — в логе появляется искажённая собственная реплика
  («Модер не подключена. Добавь ключ обмута в файл M.»). Хуже того, в окне
  ответа, где имя не требуется, он свою же реплику выполнит как команду.
  Лечится в `_say`: микрофон глохнет на время речи плюс хвост
  `audio.echo_tail_ms` на затухание колонок и реверберацию. Наушники или
  микрофон с аппаратным AEC снимают проблему полностью.
- **Распознавание не должно блокировать захват.** Whisper работает секунды;
  фрагменты уходят в очередь, разбирает отдельная задача.
- **Видеокарты для расчётов на машине владельца нет.** Проверено 29.07.2026:
  `Get-CimInstance Win32_VideoController` показывает Intel UHD Graphics,
  `nvidia-smi` не установлен. Whisper (ctranslate2) считает только на CUDA,
  то есть на NVIDIA; встроенная графика Intel и карты AMD ему недоступны, и
  `device: auto` честно остаётся на процессоре. **Предлагать «включить
  видеокарту» больше не нужно** — вопрос закрыт до смены компьютера.
  Отсюда и рычаги: `vad_filter` (не разбирать фон), `cpu_threads`, в крайнем
  случае модель полегче. Гипотеза про самосборку ctranslate2 под Python 3.14
  тоже не подтвердилась: колесо `cp314-win_amd64` существует и весит столько
  же, сколько остальные.
- **Молчаливый переход на процессор — потеря в пять раз.** `device: auto`
  спрашивает у ctranslate2 число CUDA-устройств, и раньше нуль записывался в
  debug: со стороны это выглядело как «видеокарта не нужна». Теперь причина
  пишется в INFO вместе с проверкой (`ctranslate2.get_cuda_device_count()`) и
  тем, чего обычно не хватает: cuBLAS и cuDNN (`pip install nvidia-cublas-cu12
  nvidia-cudnn-cu12`). Видеокарта у владельца простаивает — если в логе снова
  «Видеокарта не найдена», дело в библиотеках, а не в конфиге.
- **Своя ошибка объясняет себя сама, чужой нужен стек.** `ServiceRunner`
  печатал полный трейсбек на любой сбой запуска. Когда 30.07.2026 на ноуте
  Whisper не влез в память (свободным остался 1 ГБ из 16: PyCharm 2.7 ГБ плюс
  сжатие памяти 2.4 ГБ), в консоль уехало два стека ctranslate2 — и первый
  вопрос владельца был «это я что-то сломал?». Теперь `JarvisError` пишется
  одной понятной строкой без стека, всё остальное — со стеком, как было.
  Нехватка памяти при загрузке модели поднимается как `STTError` с текстом
  «закрой тяжёлые программы либо stt.model: base» (`out_of_memory` ловит и
  `MemoryError`, и `mkl_malloc`), в `__main__` у неё свой код возврата 4.
  **Запуск при этом прекращается намеренно**: без распознавания голосом
  командовать нечем, а работающий процесс без ушей — это ровно та ложь, за
  которую поправлен свободный разговор.
- **`mkl_malloc: failed to allocate memory` — это Whisper и нехватка памяти.**
  Падает не при загрузке модели, а при переборе сегментов: память выделяется
  лениво. Полный стек тут ничего не объясняет, поэтому ошибка ловится в
  `_transcribe` и превращается в предупреждение с подсказкой (`stt.model: base`).
  Фразу всё равно не спасти, но конвейер продолжает слушать.
- **«Не успеваю распознавать» — почти всегда посторонняя речь, а не слабый
  компьютер.** Whisper работает примерно в реальном времени, поэтому непрерывный
  фон (видео в колонках, разговор рядом) забивает очередь целиком. Удлинять её
  бессмысленно: это не «успеем больше», а «выполним с опозданием на длину
  очереди». Предел вынесен в `audio.pending_limit`, но лечится это наушниками
  или моделью полегче (`stt.model: base`).
- **`sounddevice` падает при импорте**, а не при вызове: на машине без звука
  бросает `PortAudioError`. Ловить нужно широко, не только `ImportError`.
- **Неточное распознавание («включи» → «в куче») не ловится фразами и
  нечётким сравнением** — шаблоны вида `включи {mode} режим` сравниваются как
  литералы. Это работа LLM-резолвера, то есть нужен ключ OpenRouter.
- **Тестовый стенд:** синтез Piper → распознавание Whisper. Ресемплить
  22050→16000 отбрасыванием сэмплов нельзя (алиасинг рушит распознавание) —
  использовать `faster_whisper.audio.decode_audio`.
- **Окно ответа нельзя проверять по часам в момент разбора.** Между речью и
  разбором лежит распознавание — секунды. Окно после «Слушаю» закрывалось,
  пока Whisper ещё расшифровывал ответную фразу, и команда терялась. Теперь
  фрагмент несёт время, когда он **прозвучал** (`_submit` вычитает длину
  фрагмента из текущего времени), и окно сверяется с ним. По той же причине
  отсчёт начинается не при распознавании имени, а после того, как «Слушаю»
  отзвучало: иначе собственная реплика съедает часть обещанного времени.
- **Звук отклика надо обрезать.** Пока он играет, микрофон заглушён, так что
  хвост тишины в файле превращается в паузу, когда ассистент уже не слушает.
  В `activation.mp3` звук занимает 0.8 с из четырёх — `trim_silence` режет
  тишину по краям, порог берётся от пика самой записи. Играет отклик
  **параллельно** с выполнением команды, а не до него: он сообщает «услышал»,
  и задерживать ради него работу незачем.
- **Число из речи приходит с лишними словами.** Шаблон «громкость {level}» на
  фразе «Джарвис, громкость на 50» отдаёт в аргумент строку «на 50», и строгое
  приведение типа отбивало команду. Требовать говорить ровно как в шаблоне
  бессмысленно, поэтому `parse_number` (в `contracts/intent.py`) вытаскивает
  число из текста, понимает и прописью («пятьдесят», «двадцать пять»), и
  отказывается, если чисел нет или их несколько. Подключено в `_coerce`, то
  есть работает для любого числового параметра любого скилла.
- **`router.aliases` молча проглатывает опечатки.** В конфиге лежали синонимы
  «погромче» → `system.volume_up`, а инструмента с таким именем в проекте не
  было никогда: резолвер писал предупреждение в лог и пропускал реплику
  дальше, то есть команда каждый раз уезжала в платную LLM. Проверять синонимы
  стоит по выводу `--check`, где напечатан весь каталог.
- **Голосовой ввод — недоверенный ввод.** Название программы проходит путь
  микрофон → Whisper → LLM → аргумент инструмента, и на каждом шаге меняется.
  Jarvis работает от администратора, поэтому строку из этого пути нельзя
  отдавать ни в оболочку, ни в `shell=True`, ни в `start`. Только сопоставление
  с известным списком и запуск найденного. То же правило для аргументов внешних
  команд: имя процесса для `taskkill` проверяется регулярным выражением, хотя и
  берётся из вывода `tasklist`.
- **«Открой видео …» — это ролик, а не программа.** Фраза начинается с
  «открой», и шаблон `открой {program}` её забирал: «открой видео, как Ян
  Топлис обманывал всех 10 лет на сайте» уходило в запуск программ. Лечится
  шаблоном `открой видео {track}` (`page.play_video`) — своих слов в нём больше,
  поэтому он проверяется раньше. То же с «открой в ютубе {track}». Шаблоны эти
  жили в скилле youtube, и при его удалении их **обязательно** нужно было
  забрать: без них дыра открывается заново.
- **Название кнопки склоняют.** «Нажми кнопку коллекции» против «Коллекция» на
  Яндекс Музыке: сравнение идёт началом слова, поэтому в варианты дописывается
  основа без окончания — одна основа покрывает все падежи. Только для русского
  и только для слов от шести букв: у английских подписей падежей нет, а от
  «лайк» осталось бы «лай».
- **Длинная фраза программой не бывает** (`MAX_PROGRAM_WORDS = 5`). «Открой
  видео, как я обманывал всех десять лет на сайте» нашло «4K Video Downloader+»
  по слову «видео» и **вызвало запрос прав администратора**. Отказ отправляет
  такую фразу дальше — в браузер, где ей и место.
- **Нечёткое сравнение — только с названием целиком.** «Открой гитхап»
  запускало «Ample Guitar»: `githap` похоже на `guitar` на 0.73, а слово
  `guitar` — часть длинного названия. Точное совпадение и совпадение краем по
  отдельным словам уместны и остаются, но нечёткое по куску названия — слишком
  слабое основание, чтобы что-то запускать от администратора.
- **Подбор по услышанному: сравнивать краем слова, а не любым куском.**
  «telegramdesktop» содержит «кто» — вопрос «кто такой трамп» открывал
  Telegram. «блокнот» содержит «окно». И **не разбирать запрос на слова**:
  «такое» похоже на «task», отчего «что такое питон» открывало диспетчер задач.
  Слова выделяются в названиях программ, но не в услышанном.
- **DEBUG в конфиге включал отладку всей системе.** Чужие логгеры своего
  уровня не имеют и берут его у корня, поэтому `level: DEBUG` заставлял numba
  вываливать в лог дизассемблер каждой компилируемой функции — сотни строк на
  фразу, наши записи в них тонули. Чёрный список шумных библиотек не помогал:
  каждая новая зависимость приносит свои. Теперь корень держится на WARNING,
  а уровень из конфига получает только `jarvis` (`_APP_LOGGERS`).
- **Удачный разбор моделью запоминается как формулировка** (резолвер `learned`,
  `router/resolvers/learned.py`, раздел памяти `commands`). Модель разобрала
  фразу, инструмент отработал — связка «эти слова означают эту команду»
  проверена делом, и со второго раза фраза обходится без модели. Тонкости, о
  которые легко споткнуться:
  * **пишется только успех.** Решение принимает диспетчер: он единственный
    знает и намерение, и результат вызова. Закрепить промах хуже, чем не
    выучить ничего;
  * **место в цепочке — после `alias`, до `llm`.** Написанное в скилле руками
    всегда главнее выученного, которое могло устареть;
  * **обобщение осторожное.** Если значение аргумента слышно в самой реплике,
    из неё выводится шаблон — но только когда своих слов остаётся не меньше
    двух и восьми букв. Иначе «включи третье видео» превратилось бы в «включи
    {control}» и поймало бы «включи свет». Не прошло — запоминаем целиком;
  * **уверенность 0.9**: ниже точной фразы, выше разбора моделью;
  * `core.chat` и `core.forget_last` не запоминаются никогда.
- **«Не сохраняй в память» не стирает, а запоминает промах** (`core.forget_last`).
  «Сработало» и «сработало так, как я хотел» — разные вещи: модель могла выбрать
  похожую команду, а на странице — соседнюю кнопку. **Простое удаление тут
  бесполезно**: модель предложила бы то же самое, разбор прошёл бы «удачно», и
  связка выучилась бы снова. Поэтому отвергнутое сохраняется как «это уже
  пробовали»:
  * у формулировки запись остаётся в виде `{"rejected": ["page.press"]}`.
    `remember` такой инструмент для этой фразы больше не запишет, а
    `LLMResolver` дописывает отвергнутое прямо в вопрос модели — «выбери
    другой». Так «попробуй иначе» получается само, без второй просьбы;
  * у кнопки — `{"rejected": {"like": [{"name": …, "sel": …}]}}` в разделе
    `sites`. Селектор выпадает из плана, подпись уходит в запреты шага `label`
    (`without_rejected`), а модели при новом обучении её даже не показывают.
  Отменяется **последнее сделанное**, а не последнее выученное: промах чаще
  вылезает при повторе — вчера запомнили, сегодня повторилось и оказалось не
  тем. Поэтому `resolve` тоже помечает совпавшую формулировку как последнюю, а
  скилл `page` помнит любое нажатие, даже если ничего не выучивал (не ту кнопку
  мог нажать и общий способ по подписи).
  Связь со скиллами — **договорённость об имени**: ядро вызывает все инструменты
  `*.forget_last` (`FORGET_TOOL` в `builtin.py`), поэтому новый самообучающийся
  скилл попадает под эту команду без правки ядра.
  **Ошибочный отказ хуже, чем ничего.** В памяти на ноуте осталось
  `«нажимай кнопку {control} на сайте» → rejected: [page.press]` — отменили в
  тот раз, когда модель выбрала не ту кнопку, хотя инструмент был верный. Такая
  запись потом **запрещает правильный разбор**: модели прямо говорится «page.press
  не предлагай». Вычищено вручную 30.07.2026 (`memory/documents/commands.json`
  на ноуте). Если владелец говорит «не сохраняй в память» из-за промаха внутри
  страницы, отменять надо кнопку, а не формулировку, — но различить это по факту
  нельзя, поэтому чистить память иногда придётся руками. Файл маленький и
  человекочитаемый; править только при остановленном Jarvis, иначе он перезапишет
  его из своего кеша. И копировать **без BOM** (scp, не `Set-Content`): с BOM
  `json.load` падает.
  Грабли при реализации: у `avoid` свой предел длины (`MAX_AVOID`). Общий с
  селекторами (6) обрезал бы как раз отвергнутые подписи — они дописываются
  последними, а у `like` встроенных запретов ровно шесть.
- **Модель с каталогом инструментов стоит в цепочке всегда** (резолвер `llm`,
  задача `intent`, function-calling). Её не «включают» и не «возвращают»: она
  срабатывает на каждой фразе, не узнанной фразами и синонимами. Если команда
  не выполнилась, а модель что-то сказала, дело не в том, что у неё не было
  инструментов, — она их видела и **отказалась выбирать**. Лечится подсказкой
  (`_INTENT_SYSTEM`: повелительное наклонение — это команда) и второй попыткой
  моделью посильнее.
- **Свободный разговор отчитывался о работе, которой не было.** Реплики, не
  разобранные ни фразами, ни моделью, уходят в `core.chat`, а тот — обычный
  чат-бот: на «включи видео» он бодро отвечал «Включаю видео», и ничего не
  происходило. Со стороны это выглядит как сломанный ассистент, а не как
  нераспознанная команда. Поймано на живой демонстрации. Лечится в системной
  подсказке `_DIALOG_SYSTEM`: там прямо сказано, что действий этот режим не
  выполняет и отвечать «включаю», «открываю», «готово» нельзя — надо честно
  признаться, что команда не понята. Правило проверяется тестом.
- **Ответ ассистента пишется в лог** (`Отвечаю: …` в `VoicePipeline._say`).
  Без этого по логу видно команду и результат, но не произнесённую фразу, — а
  разбирать приходится ровно расхождение между ними.
- **Команда браузеру уходит одному клиенту, а не всем.** `connect()` в
  `background.js` проверял «уже подключены?», потом ждал токен из файла, и лишь
  потом создавал сокет — а зовут его сразу из трёх мест (с загрузки файла, из
  `onInstalled`, из будильника). Расширение открывало два соединения, сервер
  рассылал команду веером, браузер выполнял её дважды: **«открой вкладку»
  открывало две одинаковые вкладки, «загугли» — две одинаковые выдачи**. Видно
  это было в логе по двойному «Расширение подключилось» с одним и тем же origin.
  Починено с двух сторон, и обе стороны нужны: расширение держит подключение в
  одном экземпляре (`opening`), а `WebSocketServer.send` шлёт команду **последнему**
  подключившемуся и закрывает прежнее соединение того же origin. Сервер тут не
  подстраховка, а правило: сообщения в этом сокете — приказы, а не новости, и
  разосланный веером приказ выполняется столько раз, сколько нашлось соединений.
- **«Я обновил код» и «в браузере новый код» — разные утверждения.**
  Распакованное расширение браузер сам не перечитывает, и это уже стоило целого
  разбора: Jarvis объяснял поведение страницы, которого в загруженной версии
  просто не было, а понять удалось только по отсутствию одного поля в ответе
  (`counted` есть, `saw` есть — значит версия между двумя коммитами). Теперь
  расширение сообщает свою версию в `hello`, Jarvis сверяет её с `manifest.json`
  на диске и при расхождении **предупреждает с инструкцией**. Версию в манифесте
  поднимать при каждой правке `page.js` или `background.js` — иначе проверка
  бесполезна.
- **Музыкальный сайт открывается в фоне** (`page_target(open_missing=True)`,
  просьба владельца от 30.07.2026: «он вообще не должен открывать сайт музыки,
  пусть делает исподтишка»). «Включи трек» — не повод выдёргивать человека из
  того, чем он занят: вкладка создаётся неактивной, окно не поднимается, дело
  делается молча. Заодно исчез лишний шаг: раньше звали `browser.open_site`
  (который фокусирует), потом искали на главной, потом шли в поиск.
- **Первую команду расширение может не успеть.** Служебный поток браузера
  просыпается по будильнику, и после запуска Jarvis до полуминуты его нет на
  связи. Живой случай: `--say "включи трек …"` отработал за 0.18 с, получил
  «расширение не подключено», ушёл на ютуб — а расширение поздоровалось **в ту
  же секунду**, сразу после. Теперь команды к странице ждут первого подключения
  (`_Extension.ready`, настройка `extension.await_ready`, 15 с). Пяти секунд не
  хватило — в следующий раз расширение пришло на девятой: будильник Chrome реже
  раза в полминуты не пускает, поэтому в `background.js` есть ещё и повтор через
  2 с, пока служебный поток жив. **Ждём один раз за весь запуск**: на машине без
  расширения ответ известен заранее, и тормозить каждую команду незачем. И не
  ждём, если оно уже приходило: обрыв посреди работы — дело обычное.
- **Обрыв соединения — не авария.** Расширение отключается когда угодно, и на
  Windows это прилетает в служебный обработчик asyncio уже после закрытия
  транспорта: в лог валился полный стек `ConnectionResetError`. Гасится
  обработчиком `_quiet_broken_connections` в `app.py`.
- **Файл лога подробнее консоли** (`logging.file_level`, по умолчанию `DEBUG`;
  идея владельца от 30.07.2026). Уровня два не для симметрии: консоль читают
  глазами по ходу дела, и лишние строки в ней мешают; файл читают, когда уже
  что-то пошло не так, — и нужны там как раз записи, которых не ждали.
  **Это чинит целый класс промахов.** Пока подробности писались через `info`, у
  них появлялось условие «писать, только если есть что показать» — чтобы не
  засорять консоль. Ровно такое условие обнулило диагностику на живом разборе:
  страница отвечала «я ничего не вижу», условие не выполнялось, и четыре попытки
  подряд не оставили в логе **ни строки** — со стороны Jarvis молча передумал.
  Правило теперь простое: подробности — в `debug` и **без условий**.
  Так в файл ушёл весь разговор с расширением (`Расширению:` / `От расширения:`
  в `_Extension.call`) и каждый план со страницы вместе с сырым ответом.
  Две тонкости реализации: уровень **логгера** `jarvis` ставится в самый
  подробный из двух — он решает первым, и что отсёк он, до обработчиков уже не
  дойдёт; а корень по-прежнему держится на `WARNING`, иначе подробный файл
  состоял бы из чужой отладки (numba на DEBUG печатает дизассемблер каждой
  компилируемой функции). Опечатка в названии уровня не роняет запуск.
- **Цвет — свойство консоли, и только её** (`logging.color`, `auto` по
  умолчанию; просьба владельца от 30.07.2026). Гарантия, что он не попадёт в
  файл, устроена не как «не забыть отключить», а как «некуда поставить»:
  раскрашивающий форматтер вешается ровно на консольный обработчик. В файле цвет
  ломает и `grep`, и чтение глазами, а читают файл именно тогда, когда уже
  что-то случилось.
  Красным и жёлтым — уровень; приглушённо — время, имя логгера и `debug`;
  голубым — «Распознано», зелёным — «Отвечаю». **INFO намеренно без цвета**:
  таких строк большинство, и подсветить их значит не подсветить ничего.
  Три тонкости: пометка реплики идёт полем записи (`extra={"tone": …}`), а не
  подсветкой по тексту сообщения — угадывание рассыпалось бы при первой правке
  формулировки; выравнивание колонок делается **до** раскраски, потому что
  `%(levelname)-8s` считает длину вместе с невидимыми символами; и в консоли
  Windows управляющие последовательности надо сперва разрешить
  (`ENABLE_VIRTUAL_TERMINAL_PROCESSING`, иначе PowerShell печатает их буквально).
  В `auto` цвет включается только для живого терминала, `NO_COLOR` уважается.
- **Время в логе стоит первым — и в файле, и в консоли.** В консоли его не было
  вовсе: строка начиналась с уровня. По такому логу нельзя ответить ни на один
  вопрос, ради которого его и читают: что было раньше, что позже, сколько
  заняло. Формат задаётся конфигом (`logging.time_format`, строка `strftime`),
  по умолчанию `29.07.26, 21:36:51`. Одинаковый в обоих местах намеренно:
  причину ищут то в консоли, то в файле, и разные написания времени этому
  только мешают.
- **XTTS на процессоре непригоден для диалога.** Не «медленный» — модель
  грузится минутами, и первая же реплика своего языка подвисает наглухо.
  Проверено на машине владельца: `en: xtts:male_1` подвесил ответ, пришлось
  убивать процесс. Включать только при `torch.cuda.is_available()`.
  При загрузке на CPU движок теперь пишет предупреждение.
- **Тяжёлый голос грузился в середине разговора.** `CompositeTTS.start()`
  грел только голос языка по умолчанию, второй язык загружался при первом
  обращении. Теперь греются все голоса из конфига: цена платится один раз при
  запуске, где она видна в логе. Голос по умолчанию обязателен, остальные нет —
  без английской модели разумнее работать по-русски, чем не запуститься.
- **Сбой синтеза не должен рвать разговор.** `VoicePipeline._say` ловит ошибку
  озвучки, пишет реплику в лог текстом и продолжает слушать.
- **У движка синтеза конечный алфавит.** У модели Vosk в нём 63 символа:
  кириллица и горстка знаков препинания. Нет ни цифр, ни кавычек-ёлочек, ни
  обычной двойной кавычки — посторонний символ роняет синтез с `KeyError`.
  Поймано на живом запуске: «Не нашёл ничего по запросу «...»» падало с
  `KeyError: '»'`, и то же самое случилось бы с любым числом. А текст теперь
  приходит от LLM, то есть содержать может что угодно. Поэтому в
  `normalize.py` в конце стоит белый список, числа пишутся словами (включая
  порядковые: «47-й» → «сорок седьмой»), а знаки ударения снимаются через
  `unicodedata` — просто выкинуть их нельзя, слово разорвётся пробелом
  («До́нальд» → «До нальд»).
  Проверять новые движки нужно так же: прочитать `phoneme_id_map` из конфига
  модели и убедиться, что нормализованный текст в него укладывается.
- **Голос и распознавание на сервере не гоняются вообще.** Сначала (28.07) —
  из-за качества: прогон «синтез → распознавание» показывает разборчивость, но
  не то, нравится ли голос. Потом (29.07) запрет расширен на любой запуск с
  моделями: два слабых ядра, каждый `--check` — две минуты. Остаются чтение
  конфигов моделей, сверка сигнатур API и `pytest`. Что не проверено — писать
  честно и отдавать владельцу списком.

## Голоса: вопрос закрыт

**Выбрано и подтверждено на слух: `ru: vosk:male_1`, `en: kokoro:bm_george`.**
Оценка владельца о Vosk — «имба, отлично подходит и звучит нормально». Поиск
русского голоса на этом закончен, заново его открывать не нужно.

Отвергнуто (чтобы не предлагать по второму кругу): Piper (`dmitri`, `denis`,
`ruslan`, `irina`), Silero (`eugene`, `aidar`, `baya`, `kseniya`, `xenia`),
Edge (`ru-RU-DmitryNeural`, `ru-RU-SvetlanaNeural` — плюс ощутимая задержка),
клон XTTS с `bm_george`. `edge:en-GB-RyanNeural` понравился, но проигрывает
Kokoro по задержке.

**XTTS — не план, а опция на потом.** Единственное, что он даёт, — один тембр
на обоих языках. Причём выгода уже, чем кажется: голос выбирается на всю
реплику по её языку, а латиница внутри русской фразы читается русским голосом
через `normalize.py`. То есть XTTS вступает, только когда реплика целиком
английская, — при полном переходе на английский. Пробовать его стоит на
студийном компьютере с GTX и только если разница тембров реально мешает: клон
звучит хуже, чем Kokoro сам по себе. Эталон снимается с `vosk:male_1`
(`--make-reference vosk:male_1`) либо с записи живого голоса.

роутер → Vosk/Kokoro → динамик) — проверено владельцем на живой машине,
голоса приняты. Настройка голоса закрыта, работа переходит на скиллы и LLM.
Манера речи (`persona.py`) добавлена 29.07.2026 — на слух владельцем ещё не
проверялась.

`search` и `weather` — настоящие, без ключей:

* **search** (`skills/search/skill.py`) — источники по очереди до первого
  непустого ответа, порядок в `skills.settings.search.engines`. Википедия
  (официальное API, ключа не надо, но требует `User-Agent` с контактами, иначе
  403) закрывает «кто такой» и «что такое». DuckDuckGo (`lite.duckduckgo.com`,
  разбор HTML регулярками) — всё остальное; **хрупкий**: на частые запросы
  отвечает пустой страницей, с сервера его уже блокировали. Пустой ответ — не
  ошибка, а повод идти к следующему источнику. Свой провайдер = класс с одним
  методом плюс строка в `PROVIDERS`.
* **weather** (`skills/weather/skill.py`) — Open-Meteo, ключа не требует.
  Главная тонкость: город приходит из команды в предложном падеже («погода в
  Праге»), а геокодер знает только именительный. Написания перебираются
  (`_nominative_candidates`), причём **требуется точное совпадение имени** —
  иначе на «Твери» геокодер отвечает «Тверия» в Израиле. Составные названия
  склоняются по частям («в Нижнем Новгороде», «в Ростове-на-Дону»).

* **browser** (`skills/browser/skill.py`) — сайты, поиск, окна. Кроссплатформенный:
  ссылка отдаётся системе через `webbrowser`, и открывает её тот браузер,
  который выбран в системе по умолчанию. Конкретный можно назвать в конфиге
  (`browser: chrome`) — не найдётся, откроется системный с предупреждением.
  **Поиск делается ссылкой, а не набором текста на клавиатуре.** Владелец
  просил «вводить текст в поисковую строку»; результат тот же, но эмуляция
  клавиатуры отправила бы текст в окно, которое сейчас в фокусе, а Jarvis
  работает от администратора — это худший из возможных приёмников для
  недоверенного голосового ввода. Ссылка же не умеет ничего, кроме как
  открыться: запрос кодируется `quote_plus`, схема проверяется (`safe_url`,
  только http и https) — иначе услышанное `file://` или `steam://` запустило
  бы обработчик протокола вместо браузера.
  **Из подходящих названий сайта побеждает самое длинное.** «Яндекс музыку»
  начинается с «яндекс», и открывался поиск вместо музыки — выигрывала та
  запись, что попадалась в словаре первой. Та же мысль, что и со шаблонами
  фраз: частное важнее общего.
  **Поиск ведёт открытую вкладку того же сайта, а не открывает вторую.**
  Изначально было наоборот («каждый запрос новый, переиспользовать нечего»), и
  для чужого сайта это верно: терять из-за «загугли» статью, которую читают,
  нельзя. Но «открой видео X» на уже открытом YouTube давало **вторую вкладку
  YouTube**, и владелец справедливо назвал это поломкой. Условие — тот же сайт:
  выдача сменяет выдачу, посторонняя страница остаётся. Выбор вкладки при этом
  ничего нового не требует: у `pickTab` уже есть правило «назван адрес — берём
  вкладку того же сайта», а отказ расширения («нет подходящей вкладки») и есть
  сигнал открыть новую. У `go` появился флаг `focus`: поиск показать надо, а
  поиск **внутри** «включи трек» — нет, там и так смотрят куда нужно.
  **«Вкладка это вкладка».** «Переключись на вкладку Cloud CLI» отвечало «не
  знаю такого сайта: вкладку Cloud CLI» — слово уезжало в название. Шаблонов с
  «вкладкой» было три из шести возможных; дописаны остальные.
  **«Открой вкладку X» ищет три вещи по очереди**: известный сайт, служебную
  страницу браузера («расширения», «история», «загрузки», «закладки»,
  «настройки браузера») и уже открытую вкладку по заголовку. Последние две
  доступны только с расширением: `browser://extensions` системе не отдашь —
  такой схемы она не знает, — а заголовки чужих вкладок ей неизвестны.
  Список служебных страниц закрытый, и у каждой несколько адресов: схема
  зависит от браузера, расширение перебирает их, пока какой-нибудь не
  откроется. Произвольную ссылку `chrome://` из речи не открыть ни при каких
  условиях — ни `safe_url`, ни `isInternalUrl` в расширении её не пропустят.
  **Из подходящих вкладок берётся ближайшая, а среди равных — недавняя.**
  Признаков два: близость (своя группа, своё окно, всё остальное) и давность
  (`lastAccessed`). Близость решает, какую из копий одного сайта открыть;
  давность — какую из **разных** страниц с одним названием: «МаршалТех» носят
  и страница сервера, и таблица про него, и нужна почти всегда та, с которой
  недавно работали. Когда подходит больше одной вкладки, выбор пишется в лог:
  разбирать такие случаи вслепую невозможно.
  **Порядок именно такой: своя группа, своё окно, всё остальное.** У браузера бывают десятки вкладок одного сайта, разложенных по
  группам, и «переключись на гитхаб» уводило в чужую группу — просто потому,
  что тот гитхаб оказался в списке первым. Где пользователь сейчас, расширение
  сообщает полем `current` (активная вкладка окна в фокусе); порядок считает
  `by_proximity`. Группа живёт внутри окна, поэтому первое условие строже
  второго, а не рядом с ним. Читать `tab.groupId` разрешения `tabGroups` не
  требует — оно нужно только для названий и цветов групп.
  **Алфавит записи ничего не значит.** Whisper пишет латиницей всё, что
  звучит по-английски, даже когда на странице стоит кириллица: «МаршалТех» в
  заголовке вкладки против «MarshallTech» в расшифровке. Побуквенно они не
  совпадают вовсе — совпадает согласный костяк (`jarvis/core/text/spoken.py`).
  Короткие костяки не берутся: у «YouTube» он равен «tb» и подошёл бы ко
  всему подряд, порог `_MIN_SKELETON = 5`.
  Костяк — **третий** потребитель одного и того же приёма (программы Windows,
  сайты, заголовки вкладок), поэтому он и переехал из скилла `windows` в ядро.
  Чего он не умеет и не должен: перевод. «Extensions» и «Расширения» — разные
  слова, а не разные написания, поэтому у служебных страниц просто по два
  названия в списке.
  **Разделители внутри названия ничего не значат.** «Яндекс.Музыка» с точкой
  не совпадала с «яндекс музыка» из каталога, и открывался просто Яндекс;
  «MarshallTech» слитно не совпадал с «Marshall Tech» в заголовке вкладки.
  Как написать название — вопрос вкуса того, кто его писал, и слуха того, кто
  расшифровывал, поэтому сравнение идёт по сжатой форме (`squash`: только
  буквы и цифры). Для поиска куском заголовка порог длины выше — по четырём
  буквам подряд совпало бы слишком многое.
  **Кавычки вокруг названия обязательны к снятию.** Whisper пишет «открой
  вкладку «Marshall Tech»» вместе с ёлочками, и они попадают в аргумент
  шаблона. `clean_spoken` снимает их перед любым сравнением.
  **Вкладка закрывается и по заголовку, а не только по известному сайту.**
  Настройки браузера, локальная разработка, открытый документ — их в каталоге
  сайтов нет и не будет, а «закрой вкладку Extensions» упиралось в «не знаю
  такого сайта». Короче трёх букв не ищем: снесло бы половину вкладок.
  Названия сайтов и поисковиков склоняют, поэтому сравниваются по основе
  (`_stem` отбрасывает гласные на конце): «почту» находит «почта», «в гугле» —
  google. Незнакомый поисковик — не ошибка: «найди в интернете» означает «где
  обычно».
  Закрытие окон — единственное место, где нужна ОС: скилл не импортирует
  `windows`, а зовёт `windows.close_program` через реестр; какой браузер
  запущен, узнаёт из `windows.list_programs`. Нет этих инструментов — честный
  отказ.
  **Расширение браузера (`extension/`) — основной путь, окна — запасной.**
  С ним Jarvis работает вкладками: открывает в существующем окне, переходит на
  уже открытую вкладку сайта, закрывает её. Без него всё продолжает работать
  окнами, только хуже. Каждая команда сначала пробует расширение и молча
  откатывается, если оно не подключено или не ответило за `timeout`.
  Транспорт — свой WebSocket-сервер (`jarvis/core/net/websocket.py`, RFC 6455
  в нужном объёме, без зависимостей). Направление именно такое: расширение
  слушать порт не умеет, только подключаться.
  **Порт на 127.0.0.1 доступен любой странице в браузере** — код на сайте может
  открыть `ws://127.0.0.1:8765` и притвориться расширением. Поэтому проверок
  две и обе обязательны: `Origin` (браузер подставляет сам, со страницы не
  подделать; принимаются только `chrome-extension://` и `moz-extension://`) и
  токен, который Jarvis кладёт в `extension/token.json` — страницам файлы
  расширения недоступны. Origin не спасёт от постороннего приложения на этой
  же машине, токен — от расширения, поставленного мимо нас.
  **Токен переживает перезапуск намеренно**: новый каждый раз означал бы, что
  расширение с прочитанным в память старым перестаёт подключаться до
  перезагрузки браузера.
  Служебный поток Manifest V3 засыпает через полминуты, поэтому в
  `background.js` две страховки: обмен по сокету продлевает жизнь потоку, а
  будильник (`chrome.alarms`) поднимает его и переподключает.
  Новая команда браузеру = ветка в `run()` в `background.js` плюс вызов
  `self._extension.call(...)` в скилле. Так и появилось управление страницами —
  скилл `page`, см. ниже.
  **Уже открытый сайт не открывается второй раз.** Перед `open_new` скилл
  спрашивает `windows.list_windows` и, найдя окно с этим сайтом, поднимает его
  через `windows.focus_window`. Оба инструмента `routable=False`: голосом их не
  зовут, а место в каталоге для модели они бы занимали.
  Видно при этом **только активную вкладку каждого окна** — её и показывает
  заголовок. Вкладка в глубине чужого окна снаружи браузера недоступна в
  принципе, без расширения её не достать; свои же окна Jarvis открывает через
  `open_new`, поэтому его собственные сайты находятся всегда.
  Две тонкости сравнения: имя браузера отрезается от конца заголовка
  (`page_title`), иначе «зайди на яндекс» находило бы любое окно Яндекс
  Браузера; и сравниваются слова целиком, а не куски, иначе
  «myyoutubedownloader» сошёл бы за открытый YouTube. Домен сайта в ключи не
  идёт: у `mail.google.com` это «google», и почта нашлась бы в любом окне с
  гуглом. Отключается настройкой `reuse: false`.
  Фраза **«загугли» переехала сюда из `search`**: по смыслу это «открой мне
  поиск», а не «найди и расскажи». В `search` остались формулировки, на которые
  ждут ответа голосом. Поисковика она при этом **не называет** — берётся тот,
  что в конфиге (у владельца Яндекс). Слово давно означает просто «поищи»;
  нужен именно Google — говорят «найди в гугле», и это указание сильнее
  умолчания. Whisper слышит «загугли» как два слова («за Гугли»), и
  разбор уходил в платную модель — услышанные варианты дописаны в `phrases`
  прямо рядом с правильным.
  **Латинские написания в каталоге сайтов обязательны.** Английские названия
  Whisper пишет латиницей: «зайди на YouTube» приходит именно так, и по одним
  русским ключам не находилось ничего. Плюс он глушит звонкие на конце
  («гитхаб» → «гитхап»), поэтому после сравнения по основе идёт нечёткое
  с высоким порогом (0.8): сайт открывается молча, промахнуться тут неприятнее,
  чем переспросить.
  **«Открой X» — сначала программа, потом сайт.** `windows.launch_program`, не
  найдя программу, зовёт `browser.open_site` и только потом отказывает. Порядок
  именно такой: у Steam и Telegram есть и приложение, и сайт, и обычно имеют в
  виду установленное.

* **page** (`skills/browser/page/skill.py`, подскилл браузера) — то, что делают внутри вкладки: пауза,
  следующий трек, лайк, перемотка, звук вкладки, нажатие названной кнопки
  («нажми подписаться»). Работает только с расширением: снаружи браузера
  содержимое страницы недоступно в принципе.
  **Почему отдельный скилл, а не часть browser.** Вкладки, адреса и связь с
  расширением — одна ответственность, кнопки внутри страницы — другая, и вторая
  будет расти вместе с сайтами. Импорта между ними нет: `page` зовёт
  `browser.page_run` по имени через реестр, а `browser` про кнопки не знает
  ничего. Служебные инструменты моста — `page_target`, `page_run`, `page_probe`,
  все `routable=False`.
  **У модели спрашивают не про всё.** Список кнопок для неё собирается из
  `button` и `role=button`, поэтому спросить можно только про кнопку
  (`LEARNABLE`). «Открой первое видео» — это ссылка в выдаче, её в списке нет,
  и модель в ответ выбирает что попало: на живом YouTube предложила деление
  шкалы времени, и это ушло в память как способ включить видео.
  **А если кнопку назвал владелец, выбор модели проверяется его же словами**
  (`resembles`). Угадывать тут нечего: сказанное **и есть** подпись. На «нажми
  кнопку скопировать» модель выбрала «Ещё» — нажала и запомнила навсегда.
  Теперь «Копировать ссылку» на «скопировать» похоже (общее слово, вхождение,
  костяк или 0.6 по difflib), а «Ещё» — нет, и вместо запоминания идёт отказ.
  **Служебные слова вокруг названия снимаются**: «нажми **кнопку** поделиться
  **на сайте**» — и «кнопку», и «на сайте» сказаны человеку, на кнопке их нет.
  **Обращение к модели тут — исключение, а не способ работы.** Четыре ступени,
  и до платной доходит только последняя: фраза → шаблон (бесплатно); действие →
  план из рецептов (данные, не запрос); план → страница; и лишь если ни один
  вариант не сработал — один вопрос модели со списком кнопок, ответ которого
  **уходит в память** (`memory.documents: sites`). Для этого сайта и этого
  действия вопрос больше не задаётся никогда. Ключ памяти у «нажми X» свой на
  каждую кнопку (`press:подписаться`), поэтому выучивается и это.
  **Общий способ важнее рецептов.** Он опирается на две вещи, которые есть
  везде и переживают редизайн: сам плеер (`<video>` и `<audio>` умеют
  play/pause/громкость/перемотку из коробки — на этом одном работают пауза,
  звук и перемотка вообще на любом сайте) и подписи кнопок, те самые, что
  читает экранный диктор. Селекторы конкретных сайтов (`SITE_RECIPES`) идут
  первыми, но они подсказка: устарел — план просто идёт дальше.
  **«Включи <название>» — не то же, что «нажми <название>».** Нажатие по строке
  трека воспроизведение не запускает: оно её только выбирает или уводит на
  страницу трека. Играть начинает отдельная кнопка внутри строки, и она обычно
  появляется **лишь при наведении мыши**. Отсюда шаг `item` (`page.play_item`):
  найти строку по названию → навести (`pointerover`/`mouseover`) → нажать внутри
  кнопку по подсказке (`PLAY_HINTS`) → если её нет, нажать саму строку и через
  400 мс дожать плеер, если тишина. Видимость у кнопки-подсказки не проверяется
  намеренно: до наведения она скрыта, и с проверкой её не найти никогда.
  Без этой команды «включи Midnight City» уходило в модель, а та изобретала
  `page.control(play, site=youtube)` — и включала соседнюю вкладку.
  **Из подходящих строк побеждает самая тесная.** У списка треков подпись
  начинается с первого трека, и выбирался весь список: «i need your love oliver
  nelson & tobtok remix… midnight city… the reason…». Теперь среди совпавших
  берётся элемент с самой короткой подписью.
  **У кнопки воспроизведения часто нет подписи вовсе** — внутри одна иконка.
  Поэтому после поиска по подсказке идёт поиск по атрибутам:
  `[data-test-id*="PLAY" i], [class*="play" i], [aria-label*="play" i]`.
  **Не нашли — расширение присылает список кнопок рядом** (`buttons`), и скилл
  пишет его в лог. По такому списку рецепт сайта дописывается точно, а не
  наугад: разметку чужого плеера иначе приходится угадывать вслепую.
  **Название совпадает целиком далеко не всегда.** Оно проходит путь микрофон →
  Whisper → шаблон фразы и обрастает по дороге лишними словами: «нажми на видео,
  как я на топлес обманывал всех 10 лет» против «Как я обманывал ВСЕХ 10 лет |
  Ян Топлес» на странице. Подряд эти строки не совпадают нигде, поэтому вторым
  заходом считается доля слов просьбы, найденных в подписи (`score` в `page.js`).
  Порог высокий — 60% слов и не меньше двух, — иначе слово «видео» открывало бы
  первое попавшееся. Совпадение целиком всегда главнее частичного, а при равном
  совпадении у кнопок побеждает первая на странице (у ролика это лайк ролика, а
  не лайк комментария), у строк списка — самая короткая подпись.
  **«Включи <трек>» — это «найди и включи», и ищем на самой странице.** Три шага,
  ровно как это делает человек: нажать «Поиск» (действие `search`), напечатать
  название (`type` с `submit`), включить верхний результат. **Адресом выдачи это
  делать нельзя, хотя так проще** — и сначала было сделано именно так, за что
  владелец справедливо и высказался: переход по ссылке перезагружает приложение
  сайта целиком и **глушит то, что играло**. Ради «включи следующий трек» терять
  текущий недопустимо, а вдобавок после перезагрузки Jarvis ещё несколько секунд
  смотрел на недорисованную страницу. Нажатия и печать — те же шаги, которыми уже
  работают «нажми поиск» и «введи в поиск», то есть проверенный путь.
  **Искать имеет смысл только там, где есть своя строка поиска** (`SEARCHABLE`).
  С открытой веб-панелью Jarvis однажды нашёл в тексте прошлого разговора ссылку
  со словами просьбы и нажал её.
  **Ищем только когда не нашли.** «Нашли, но тишина» повторного поиска не
  заслуживает: строка на месте, все способы включить её страница уже перебрала, а
  второй круг — это десяток нажатий по чужой разметке впустую.
  **Нажатие — не то же самое, что звук.** Живой случай: на Яндекс Музыке строка
  нашлась, кнопка «Воспроизведение» нажалась, ассистент отчитался «включаю» — и
  тишина. Поэтому у шага `item` с `play: true` успехом считается только
  появившийся звук: не появился — нажимаем саму строку, потом дожимаем плеер, и
  только тогда отвечаем `played: false`. Скилл на это отвечает отказом «нашёл, но
  включить не получилось», а не бодрым «включаю» — тот же грех, за который
  поправлен свободный разговор.
  **«Играет ли» нельзя спрашивать у `players()`.** Тот фильтр отбирает
  «настоящие» плееры по `readyState`, длительности или сдвинутому времени, а у
  только что созданного плеера нет ничего из этого — и «уже играет» читалось как
  тишина. Из-за этого Jarvis нажимал трек, не верил, что получилось, шёл нажимать
  строку (а это переход на страницу трека), потом дожимал плеер — «слишком много
  раз тыкал», по словам владельца. `sounding()` смотрит на **все** `video/audio`
  и только на `paused`/`ended`/`muted`: `paused` переключается сразу, как сайт
  вызвал `play()`. `muted` считается тишиной намеренно — на YouTube наведение
  мыши запускает беззвучный предпросмотр, а наведение делает как раз `item`.
  **«Включи X» решает открытый сайт, а не модель.** Правило владельца от
  30.07.2026: «если мы на Яндекс Музыке, то в 95% случаев я про музыку; с ютубом
  так же». Реализовано не новым инструментом, а убиранием лишнего: `play_item`
  ищет **на том сайте, который открыт**, то есть уже делает ровно это, — а
  «включи ролик» из каталога для модели убран (`routable=False`). Двух
  инструментов на одну просьбу быть не должно: пока оба были в каталоге, модель
  выбирала между ними наугад и уводила с открытой Яндекс Музыки на ютуб (притом
  послушно, в той же вкладке).
  Фразы, где про видео сказано прямо («включи видео X», «включи трейлер X»),
  у `play_video` остались — `routable` влияет только на каталог для модели.
  Если открытый сайт искать не умеет (или браузер закрыт), команда идёт на свой
  сайт: `music_site` для трека, `video_site` для ролика (`otherwise` в `_act`,
  оба в конфиге). Сначала тут был жёстко ютуб, и это была ошибка: «включи
  **трек** Dua Lipa» с открытым посторонним сайтом включало клип, хотя слово
  «трек» сказано прямо, а Яндекс Музыка была открыта рядом. **Тишина после
  нажатия сюда не входит**: там нашлось и нажалось, уводить владельца на другой
  сайт неверно.
  **На сайте, где искать нечем, и на странице делать нечего.** Это стоило двух
  заходов. Открыта была веб-панель, а в ней висел текст прошлого разговора —
  вместе со ссылкой `youtube.com/results?search_query=dua+lipa+-+break+my+heart`.
  Слова просьбы нашлись в ней все, ссылка «совпала» лучше любого трека, Jarvis её
  нажал и честно доложил «нашёл, но не заиграло»; музыкальный сайт при этом стоял
  рядом открытым и не получил ни одной команды. Теперь при `search` без своей
  выдачи у сайта страница даже не осматривается. Плюс в `page.js` голый адрес
  вообще не считается подписью — названием трека он не бывает.
  **Скилл `youtube` удалён владельцем 30.07.2026** («он не нужен»), а фразы про
  видео переехали в `page.play_video`. Забрать их было обязательно: «открой видео
  Мегамозг» иначе снова достаётся шаблону «открой {program}» из запуска
  программ — а это ровно тот случай, когда голос вызвал запрос прав
  администратора. В каталог для модели `play_video` не идёт: «включи X» решает
  открытый сайт, а тут про видео сказано прямо.
  **Переход по адресу нельзя ждать по событиям загрузки.** Одностраничные сайты
  меняют выдачу своим кодом, и «загрузка завершена» либо приходит от прежней
  страницы, либо не приходит вовсе: `loaded` честно выжидал пять секунд и
  возвращал старую вкладку, после чего трек искался на **предыдущей** выдаче. В
  логе это выглядело как «нашёл не тот трек», хотя нужный был на экране.
  Признак прямой: адрес вкладки перестал быть прежним (`arrived` в
  `background.js`) — он меняется и при обычном переходе, и при подмене истории.
  **Ошибка внутри страницы обязана попадать в лог** (`broke` в ответе). Это
  стоило нескольких заходов разбора: шаг падал с исключением, оно ловилось «один
  вариант не вышел — пробуем следующий», и наружу уходил ответ, неотличимый от
  «на странице ничего не нашлось». Четыре попытки подряд, ни одной причины.
  **Нажимать надо кнопку, а не иконку внутри неё.** Тот самый случай: признак
  «похоже на play» (`[class*="play" i]`) совпал с `<svg
  class="…playButtonIcon…">` **внутри** кнопки, а у SVG нет метода `click()` —
  вызов свалился, план оборвался молча. Теперь от находки по признаку поднимаемся
  к ближайшему нажимаемому (`closest`), а само нажатие идёт через `press()`:
  сперва `click()`, при отказе — событие мыши. Уронить план нажатие больше не
  может.
  **Селектор верхнего результата обязан быть вложенным.** Разбор сохранённой
  страницы (владелец прислал её файлом — самый полезный артефакт за всё время):
  `PlayButtonWithCover_playButton` встречается **38 раз**, и первым идёт кнопка в
  **боковом меню** — «Вайбы отдыха». То есть «включи трек» запускало бы плейлист
  из сайдбара. Правильный якорь — `SearchBestResultsTrackBlock_root`: ровно один
  на странице, и означает «лучший результат, и это трек» (у артиста блок другой).
  Ещё из той же страницы: `data-test-id` у Яндекс Музыки больше **нет вовсе**
  (были в прежней версии сайта), зато `aria-label` богатые и с видом сущности —
  «Трек Levitating», «Артист Dua Lipa», «Клип …». Поле поиска — единственный
  `input[type="search"]`.
  **Сравнение по словам не находит трек, если в просьбе есть артист.** «Dua Lipa
  — Levitating» против подписи «Трек Levitating»: из трёх слов просьбы совпадает
  одно, 0.33 при пороге 0.6 — то есть верный ответ отбрасывается, а караоке-копии
  («Levitating (Dua Lipa Cover)») проходят, потому что повторяют оба слова. Это
  ещё один довод за «верхний результат сайта», а не за подбор по названию.
  **На своей выдаче верхний результат главнее сравнения слов** (шаг `item`,
  поле `prefer`). Порядок расставил сайт — по всему, что он знает о треках; у нас
  есть только услышанное название, уже искажённое распознаванием, и ранжировать
  им поверх готового порядка значит менять хорошее знание на плохое. Живой
  случай: «Dua Lipa Break My Heart» пришло как «2, липа Brake My Heart», верхней
  карточкой Яндекс поставил трек Dua Lipa, а совпадение по словам увело в ремиксы
  посторонних артистов ниже — «break» и «heart» нашлись и там. **Действует только
  на той выдаче, которую Jarvis открыл сам**: на странице, открытой владельцем,
  никакого «верхнего результата» нет, и там название решает всё. Селекторы берутся
  из рецепта `first` этого сайта — того же, что у «включи первый результат»: один
  источник на две команды. Видимость у такой кнопки не проверяется (на большой
  карточке она появляется при наведении) — та же причина, что и у кнопки внутри
  строки.
  **Обёртка списка отвечает просьбе лучше любой строки.** Она склеивает подписи
  всех строк подряд, поэтому слов просьбы в ней больше: «включи трек Dua Lipa
  Break My Heart» выбрало «new rulesdua lipa03:29let you break my heart
  againmorlix…», то есть всю выдачу Яндекс Музыки целиком. Тесной подписи тут
  недостаточно — у обёртки и совпадение выше. Правило другое: **побеждает самый
  внутренний** — элемент, внутри которого лежит другой подходящий, отбрасывается
  (`contains` в `bestMatch`).
  **Вслух называется то, что просили, а не подпись найденного.** Из того же
  случая: ассистент честно прочитал вслух всю склеенную выдачу. Подпись остаётся
  в логе — там она и нужна.
  **«Идёт ли звук» ничего не значит, когда звук уже идёт.** На выдаче Яндекс
  Музыки играл посторонний трек, и любое нажатие сошло бы за успех — «звучит же».
  Поэтому сравнивается слепок состояния плееров (`snapshot`/`restarted`).
  **Сравнивать адрес источника бесполезно, и это стоило отдельного захода.**
  Яндекс Музыка играет через MediaSource: `src` — это `blob:`, созданный один
  раз, и смену трека он **переживает**. Флага паузы тоже мало — музыка играла до
  нажатия и играет после. Работают два других признака: **длительность** (у
  другого трека она другая) и **сброс времени** (у нового трека оно идёт назад, а
  при обычной игре только вперёд). Живой симптом был обманчив: с открытой
  страницей трек включался, а ассистент отвечал «нашёл, но включить не
  получилось».
  **Пустая страница и полная без совпадений — разные болезни.** Первая лечится
  ожиданием, вторая названием, а в логе выглядели одинаково: список видимого
  писался только «если есть что показать», и четыре пустых попытки подряд не
  оставляли ни строки — со стороны Jarvis молча передумал. Теперь в ответе есть
  число осмотренных элементов (`counted`), и ноль пишется отдельной строкой.
  **Ответ берётся из главного кадра, а не из первого ответившего.** Порядок
  ответов от кадров браузер не обещает; когда не сработал никто, наружу уходил
  первый попавшийся — и это оказывался рекламный фрейм с пустой страницей.
  Сортировка по `frameId` в `inPage`.
  **Кнопка, ставшая паузой, — тоже ответ «играю».** Одного звука мало: Яндекс
  Музыка сперва идёт за ссылкой на файл, и в первые полсекунды тишина законна. В
  этом зазоре Jarvis успевал нажать строку — а это переход на страницу трека — и
  дожать плеер, хотя трек уже играл. Поэтому ждём **любого** из двух признаков
  (`awaitStart`): звук или подпись кнопки из `PAUSE_WORDS`. И если кнопка
  показывает паузу **до** нажатия, значит этот трек играет прямо сейчас: нажать
  её означало бы остановить музыку в ответ на «включи».
  **Ожидания внутри страницы складываются и упираются в предел расширения.**
  Секунда на проверку звука × три способа × четыре попытки поиска = 18 секунд на
  одну команду и три «расширение не ответило» подряд. Поэтому: ждём звука
  сотнями миллисекунд, а не секундами (ждём-то обработчик нажатия, не загрузку
  трека); повторяем поиск только пока **не нашли** — «нашли, но тишина» второго
  круга не заслуживает, все способы уже перебраны внутри страницы; и
  `browser.extension.timeout` поднят до 12 с, потому что ожидание тут законное.
  **Что видно на странице — пишется в лог при любой неудаче** (`saw` у шага
  `item`, «На странице видно: …»). Разбирать «почему не нашёл» без этого
  невозможно: причин две — не то услышанное название и не дорисованная выдача, —
  а выглядят они одинаково. Список — **ближайшее к просьбе**, а не первое на
  странице: сначала в лог уезжало «главная; поиск; моя волна…», то есть боковое
  меню, и по нему сказать было нечего. Мера близости для отчёта своя, без порога:
  одно общее слово нажатия не заслуживает, а в отчёте важно.
  **Класс из сборки — не селектор.** В `buttons` уезжало по десятку склеенных
  классов на кнопку (`uwk3hf… IlG7b1… undefined …`). Берётся один и осмысленный:
  с двойным подчёркиванием, то есть имя из CSS-модуля
  (`PlayButtonWithPosition_playButton__7cfDQ`).
  **«Пролистай страницу» — своя команда** (`page.scroll_page`, шаг `scroll`).
  Кнопки для этого нет ни на одном сайте, и модель разобрала просьбу как
  перемотку назад — из всего каталога это было самое близкое. Направление обязано
  стоять в шаблоне фразы (`пролистай {where}`): без него «вверх» и «вниз» — одна
  и та же фраза с одним и тем же аргументом по умолчанию.
  **«Переключить воспроизведение» модель понимает как «следующий трек».** На
  Яндекс Музыке она на этот вопрос выбрала «Следующая песня», и это ушло в
  память навсегда (вычищено вручную 30.07.2026). Поэтому `toggle` убран из
  `LEARNABLE`: спрашивать тут не о чем — у переключения есть и общий способ (сам
  плеер), и подписи кнопок, а если плеера на странице нет, то и переключать
  нечего. Формулировка в `INTENT_TEXT` тоже переписана на однозначную.
  **«Перейди на главную» — своя команда, а не нажатие логотипа** (`page.home`).
  Логотип — ссылка, а список для модели собирается из кнопок, поэтому «нажми на
  лого YouTube» дважды упёрлось в «модель не нашла кнопку». Адрес берётся из
  самой вкладки (`origin_of`), переход — в ней же.
  **«Введи в поиск …» печатает на странице, а не открывает поисковик**
  (`page.type_in`, шаг `type`). Живой случай: на Яндекс Музыке нажали «поиск»,
  сказали «введи в поиск Don't Stop Me Now» — и открылась выдача Яндекса.
  «Найди на Яндекс Музыке» и «загугли» — разные просьбы.
  Это **не** та эмуляция клавиатуры, которой мы избегаем: текст кладётся в
  конкретное поле конкретной вкладки и уйти в терминал не может. Значение
  ставится через родной сеттер — иначе React с Vue его не замечают.
  **Подпись сравнивается началом слова, и этого мало.** «like» внутри
  «dislike» — ровно противоположная команда, но по-русски отрицание стоит
  **перед** словом: «не нравится» содержит «нравится» целиком и словом тоже.
  Поймано на живой Яндекс Музыке — «поставь лайк» нажимало дизлайк. Поэтому у
  шага `label` есть список запретных подписей (`avoid`), и запрет сильнее
  совпадения. Туда же «убрать» и «отменить»: у уже лайкнутого трека кнопка
  называется «Убрать отметку „Нравится“», и это отмена лайка, а не лайк.
  **Границей слова считается любой не-буквенный символ.** YouTube пишет
  «Поставить отметку "Нравится"» — слово в кавычках, и сравнение краем слова
  не находило его вовсе: перед словом стоит кавычка, а не пробел.
  **Название сайта в «поставь ютуб на паузу» — пожелание, а не требование**
  (`soft=True` у `pause` и `play`). Остановить просят звук, и молчать из-за
  неудачно названной вкладки хуже, чем выполнить. У `press` и явного `control`
  название остаётся требованием: нажать кнопку не на том сайте — уже не мелочь.
  **План — список вариантов, а не последовательность.** Выполняется первый
  сработавший; порядок источников: свой рецепт из конфига → выученное из
  памяти → встроенный рецепт → общий способ. Человеческое впереди: если
  владелец что-то поправил руками, выученное когда-то могло уже устареть.
  **Модель отвечает номером кнопки, а не селектором.** Попроси селектор —
  получишь выдуманный, она честно допишет то, чего на странице нет. Номер можно
  только либо назвать верно, либо промахнуться по списку, который у нас на
  руках.
  **Вкладка ищется до сборки плана** (`browser.page_target`): не зная сайта, не
  знаешь и рецепта. Порядок выбора: названный сайт → вкладка, из которой **идёт
  звук** (`tab.audible`) → вкладка в фокусе. Звучащая вкладка тут главный
  признак: «стоп» относится к тому, что играет, а не к тому, куда смотрят.
  Фокус при этом не перехватывается — пауза не должна дёргать окно.
  **Но не для всего.** «Включи первое видео» относится к тому, куда смотрят,
  даже если в соседнем окне играет музыка, — поэтому у `page_target` есть флаг
  `active`, а у `_act` — `focused`. Звук ищут команды про звук, а команды про
  содержимое — глаза.
  **Расширение ждёт загрузки страницы** (`loaded()` в `background.js`, до 5 с).
  Команда часто идёт сразу за открытием вкладки — «включи первое видео» после
  поиска, — а нажимать ещё не на что: разметки нет.
  **«Включи трейлер X» ищет на видеосайте** (`page.play_video`): открывает его,
  идёт в поиск сайта, берёт верхний результат. Ключ YouTube API для этого не
  нужен — всё делают браузер и расширение.
  **Из голоса в страницу уходят только данные.** Исполняемый код лежит в
  `extension/page.js` и приходит из расширения; селектор попадает в
  `querySelector`, подпись — в сравнение строк. Набор шагов закрытый (`media`,
  `label`, `click`), и всё, что в него не уложилось, отбрасывается дважды: в
  Python (`validate_plan` — источники ненадёжны: конфиг пишет человек, память
  лежит файлом, кнопку выбирает модель) и ещё раз в самой странице.
  **Полноэкранного режима среди шагов нет намеренно.** Браузер разрешает его
  только по живому нажатию человека, синтетический клик такого права не даёт —
  команда молча не работала бы. По той же причине `play()` иногда отказывает,
  и тогда план идёт к кнопке сайта.
  **JS проверяется на node**: `extension/selftest.js` подделывает страницу и
  прогоняет интерпретатор (23 проверки), `tests/test_extension_page.py`
  запускает его из pytest и пропускает тест, если node не установлен.
  Заглушка `youtube.pause` удалена: она отвечала «Пауза.» и не делала ничего, а
  две команды с одной фразой спорили бы между собой.

* **telegram** (`skills/telegram/skill.py`) — прочитать, пересказать, ответить
  **от своего аккаунта** (Telethon, MTProto). Бот не годится: он видит только
  чаты, куда его добавили, а нужна обычная переписка. Отсюда `api_id` и
  `api_hash` вместо токена.
  **Вход делается один раз и руками**: `python skills/telegram/login.py`.
  Телеграм присылает код в приложение — голосом его не продиктуешь, а запуск
  ассистента не должен зависать в ожидании ввода. Скрипт лежит рядом со скиллом
  и читает те же настройки; загрузчик его не трогает, он ищет только `skill.py`.
  **Файл сессии равносилен входу в аккаунт** — ни пароля, ни кода к нему не
  нужно. Живёт в `memory/` (весь каталог в `.gitignore`), плюс правило
  `*.session`. Звёздочка обязательна: шаблон `.session` совпадает только с
  файлом, который так и называется, — те же грабли, что с `memory/` без слэша.
  **Telethon импортируется лениво, внутри метода.** Импорт наверху сломал бы и
  `--check`, и весь запуск на машине, где пакет не установлен: он необязателен,
  как faster-whisper и piper.
  **Кому уйдёт сообщение — решает не распознавание.** Имя идёт через Whisper и
  модель, а цена ошибки тут не «команда не сработала», а письмо, прочитанное
  чужим человеком. Поэтому имя сверяется со списком реальных диалогов
  (`match_chat`: формы имени → начало слова → костяк → нечёткое от 0.8), и при
  неуверенности — отказ с подсказкой «может быть, вот эти?».
  **«Напиши маме буду через час» разбирается по точности совпадения**
  (`split_request`). Голосом не диктуют двоеточий, имя и текст приходят одной
  строкой. «Самое длинное совпадение» съедает начало сообщения («настя ко я»
  вместо «Настя Ко»), «самое короткое» рвёт составные имена — поэтому
  побеждает то разбиение, где длина услышанного ближе всего к длине настоящего
  названия.
  **Модель зовётся ровно в одном месте — в пересказе.** Список чатов и чтение
  обходятся запросом к API: платить за то, что делается кодом, незачем.
  Новое сообщение — это факт, поэтому уходит в шину событием
  `telegram.message.received`; слушать его может кто угодно.

* **windows** (`skills/windows/skill.py`) — запуск программ, блокировка ПК,
  закрытие, список процессов, громкость. Только Windows, на сервере не
  запускался ни разу: `platforms=("windows",)`, поэтому вся логика подбора
  вынесена в чистые функции и покрыта тестами, которые идут где угодно.
  **Владелец запускает Jarvis от администратора** — отсюда главное правило:
  услышанное название никогда не попадает в оболочку. Оно сопоставляется с
  каталогом (меню «Пуск» + конфиг + встроенные средства), запускается только
  найденное, `os.startfile` вместо команды строкой, `shell=True` нет нигде.
  Не нашлось — отказ.
  Подбор названия оказался главной сложностью: Whisper пишет английские
  названия кириллицей («обс», «фотошоп»), а в меню они полные («Adobe Photoshop
  2024»). Работает четыре ступени: точное совпадение → совпадение краем слова →
  согласный костяк (гласные на слух плывут: «зум»/«zoom», «фотошоп»/«photoshop»,
  правило `tion`→`shn`, `ph`→`f`, `c`→`k`→`kh`→`h`) → нечёткое сравнение.
  Проверено на 30 названиях, ложных срабатываний ноль.
  Каталог собирается из четырёх мест: меню «Пуск», рабочий стол (Steam и часть
  установщиков пишут ярлык только туда), папки `Program Files/Имя/Имя.exe`
  (так нашёлся Soundpad — ярлыка он не оставляет) и библиотеки Steam из
  `libraryfolders.vdf`. После установки новой программы — «обнови список».
  **Закрытие ищет не только по имени процесса, но и по заголовку окна**:
  FL Studio работает как `FL64.exe`, и по именам процессов не находился.
  Заголовки даёт `tasklist /fo csv /nh /v`.
  **Окно принадлежит не тому процессу, который запускали.** Интерфейс Steam
  с переезда на Chromium рисует `steamwebhelper.exe`, у `steam.exe` видимых
  окон нет вовсе — поэтому «закрой стим» отвечал «Steam и так свёрнут» при
  открытом на весь экран Steam. Лечится `helper_pids`: если у главного
  процесса окон не нашлось, запрос уходит процессам, чьё имя **начинается**
  с его имени. Именно по имени процесса, а не по заголовку окна: заголовок
  «Steam» бывает и у папки в проводнике. Сеть расширяется только после
  неудачи — пока окно нашлось у самой программы, к соседям не лезем.
  **Совпало с заголовком окна — закрывается окно, совпало с именем процесса —
  закрывается программа.** Разница принципиальна для браузера: все его окна
  принадлежат одному процессу, и «закрой YouTube» отправляло запрос всем
  окнам сразу, браузер не исчезал, а следом его добивал `taskkill` — вместе с
  остальными вкладками. Теперь при совпадении по заголовку `close_windows`
  получает `title=` и трогает ровно это окно, исчезновения процесса никто не
  ждёт и до `taskkill` дело не доходит. Не нашлось окна — отказ, а не «тогда
  закроем что-нибудь ещё». Побочно это чинит и редакторы: раньше `taskkill`
  прилетал через четыре секунды поверх диалога «сохранить изменения?».
  **Закрытие и убийство — разные команды.** `close_program` («закрой X»)
  убирает окно, `kill_program` («убей X», «заверши процесс X») снимает процесс
  с `/f`. Разделены потому, что при убийстве теряется несохранённое, и это не
  то, что обычно имеют в виду, говоря «закрой».
  Обычное закрытие перебирает способы: своя команда выхода (`quit_commands`
  в конфиге) → `WM_CLOSE` окнам (`close_windows`, то же, что Alt+F4) →
  `taskkill`. `WM_CLOSE` шлётся **окну по номеру процесса**, а не клавишами:
  нажатие ушло бы в то окно, что сейчас в фокусе, а это может быть что угодно.
  **Для программ из трея (`TRAY_APPS`, туда входит `steam.exe`) убранное окно
  и есть результат**: процесс остаётся жить намеренно, ждать его исчезновения
  и добивать `taskkill` нельзя. Без этого правила «закрой стим» выходило из
  Steam целиком, ломая загрузки и оверлей. Список расширяется через
  `tray_apps` в конфиге.
  Громкость — единственное место, где нужен внешний пакет (`pip install -e
  ".[windows]"`). У pycaw поменялся API: `GetSpeakers()` раньше отдавал сырой
  COM-объект с методом `Activate`, теперь — обёртку `AudioDevice` со свойством
  `EndpointVolume`. Старый вызов на новой версии падает с `AttributeError`,
  поэтому `endpoint_volume()` поддерживает оба.

**Скиллов-заглушек больше нет** — удалены 30.07.2026 по просьбе владельца
(«они только мешаются»): `youtube` (всё делают `browser` и `page`; фразы про
видео переехали в `page.play_video`) и `esp32` (платы пока нет, писать будем с
живым контроллером в руках). Событийную часть шины после этого показывает
`telegram.message.received` — единственный оставшийся пример факта в шине.
Wake word по звуку (openWakeWord) — только протокол.

## Токены: где они уходят

Владелец платит за OpenRouter, поэтому расход — проектное ограничение, а не
мелочь. Порядок величин важнее конкретной модели.

- **Главный расход — задача `intent`.** Она срабатывает на каждой фразе, которую
  не узнали `phrase` и `alias`, и тащит с собой каталог инструментов в
  function-calling: 22 инструмента ≈ **2400 входных токенов на фразу**. Сам
  вопрос при этом весит 20 токенов. То есть 99% платы — за каталог.
- **Отказ дешёвой модели стоит дороже, чем вторая попытка.** Дешёвая модель
  ошибается в одну сторону: видит каталог и всё равно отвечает текстом. Реплика
  уходила в свободный разговор — то есть деньги тратились всё равно, а команда
  не выполнялась. Худший из возможных исходов. Поэтому `router.intent_tasks` —
  список: `[intent, intent_strong]`. Вторая модель спрашивается **только при
  отказе первой**, то есть платим лишь за неудачные разборы. Цена ошибки в
  другую сторону: обычный вопрос («как дела») тоже получит вторую попытку,
  и это ~$0.0004 сверху. Не устраивает — оставить одну задачу в списке.
  Опечатка в названии задачи ловится при сборке (`_intent_tasks` в `app.py`),
  а не в рантайме: те же грабли, что с `router.aliases`.
- **Удачные разборы копятся сами** (резолвер `learned`): одна и та же
  формулировка платит модели один раз в жизни, а не каждый раз. Живая речь
  однообразна — «заблокируй ноутбук» говорится одними словами месяцами.
- **Поэтому лучшая экономия — не звать модель.** Фраза, добавленная в `phrases`
  скилла, обрабатывается бесплатно и мгновенно. `LLMResolver` пишет в лог
  каждую фразу, которую пришлось разбирать моделью, — это готовый список
  кандидатов в `phrases`.
- **Служебные инструменты в каталог не попадают** (`@tool(routable=False)`):
  `core.reload_skill`, `core.set_model`. Голосом их не зовут, а вес они имели.
- **Выход дороже входа в 4–10 раз**, поэтому `max_tokens` урезаны до 200–300:
  реплику всё равно произносят вслух, длинную никто не дослушает.
- **Расход считается сам.** `LLMService.spending` копит запросы, токены и
  стоимость; OpenRouter возвращает цену в долларах, если послать
  `usage: {include: true}` — свой прайс-лист в коде держать не нужно. Итог
  пишется в лог после каждого запроса и доступен по команде «сколько
  потрачено» (`core.spending`).
- **Идентификаторы моделей у OpenRouter неочевидны.** В конфиге стоял
  `anthropic/claude-haiku-4-5`, а в каталоге он называется
  `claude-haiku-4.5` — через точку. Сверяться нужно с
  `https://openrouter.ai/api/v1/models` (открыт без ключа, там же цены и
  поле `supported_parameters`, где видно поддержку `tools`).

**Модель не знает, какой сегодня день.** В системную подсказку `core.chat`
подставляется текущая дата и время (`_now_line`), иначе на «какой сегодня
день» она выдумывает.

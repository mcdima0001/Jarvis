# CLAUDE.md — контекст проекта Jarvis

Файл для восстановления контекста, если сессия потеряна. Читается автоматически
при старте. Держать в актуальном состоянии обязательно.

## О проекте

Голосовой ассистент для управления домашней студией: компьютер, ESP32, свет,
датчики, Telegram, YouTube, поиск. Репозиторий `mcdima0001/Jarvis` (приватный),
рабочая копия `/root/Jarvis`.

**Это фундамент, а не готовый продукт.** Приоритеты владельца, по важности:
архитектура → чистый код → простота расширения. Функциональности намеренно
немного; ценность в том, что новая возможность добавляется файлом в `skills/`,
а любая часть системы заменяется без переписывания остального.

## Общение и рабочие правила

- К пользователю обращаться **на «ты»**, по-русски.
- Идентификаторы в коде английские, докстринги и документация — русские.
- **Заканчивая работу — коммитить и пушить** в `main` без напоминаний.
- **CLAUDE.md обновлять** при значимых изменениях архитектуры или состояния.
  Новую находку — не сюда, а в `docs/lessons.md`, в свой раздел: этот файл
  читается в начале каждой сессии и за него платят контекстом всегда.
- **Время смотреть по часам в логе, а не по календарю.** Владелец пишет не по
  одному разу в день: за вечер проходит десяток запусков и полдюжины коммитов.
  Слова «вчера» и «позавчера» в разборе почти всегда неверны — и сбивают с
  толку, потому что «правка вчерашнего дня» на деле сделана сорок минут назад.
  В логе есть точное время; на него и ссылаться.

## Окружение

```bash
cd /root/Jarvis
.venv/bin/python -m pytest -q            # 993 теста, около сорока секунд
.venv/bin/python -m ruff check .         # линтер: осиротевшие импорты и прочий мусор
.venv/bin/python -m mypy                 # типы: py.typed обещан, значит проверяется
.venv/bin/python -m jarvis --check       # отчёт о сборке, ~6 с, без моделей
```

**Линтер и типы стоят в CI рядом с тестами** (08.09.2026). Набор правил ruff
выбран не по вкусу, а по тому, что он реально ловит: девять из первых двенадцати
находок оказались осиротевшими импортами после правок — тем самым мусором,
который в журнале записан как признак недоделанной замены. Стилистики в наборе
нет намеренно. mypy не строгий: проект зовёт библиотеки без типов (soundcard,
vosk, telethon), и требовать аннотаций от них значит утонуть в заглушках.

**Моделей на сервере не поднимать** (просьба владельца от 29.07.2026): два
слабых ядра, Whisper с Vosk грузятся две минуты. Поэтому `--check` теперь
стартует систему без звука, распознавания и синтеза (`start(models=False)` →
`ServiceRunner.start_all(skip_heavy=True)`) — конфиг, скиллы и каталог
инструментов он проверяет и так. Полный запуск и `--say` — только у владельца;
что нужно проверить, отдавать ему списком.

```bash
# это выполняет владелец у себя, не мы
python -m jarvis                                       # живой запуск с микрофоном
python -m jarvis --say "какая температура"             # одна команда, ответ голосом
python -m jarvis --say "включи трек X" --no-voice      # то же, но молча и мгновенно
```

**Уши и голос поднимаются по отдельности** (`needs=EARS|VOICE` у сервисов,
`app.start(ears=…, voice=…)`). Одного флага «тяжёлый» не хватило: `--say`
получает команду текстом, и Whisper ему не нужен — а грузился вместе с
микрофоном. `--no-voice` снимает и синтез: Vosk на ноуте владельца поднимается
**полторы минуты**, а для проверки маршрутизации хватает напечатанного ответа.

**Логи с ноута лежат локально** — `/root/jarvis-logs/` (настроено 01.08.2026).
Забирает их systemd-таймер `jarvis-logs.timer` раз в десять минут скриптом
`/root/bin/jarvis-logs`; перед разбором можно дёрнуть его руками, это секунда:

```bash
/root/bin/jarvis-logs            # догнать прямо сейчас
ls /root/jarvis-logs/            # jarvis-2026-08-01.log и остальные
```

Устройство: **тяга, а не толкание**. Сервер сам ходит на ноут по `ssh laptop`
(Tailscale, доступ с 30.07.2026), поэтому на ноуте ничего ставить и настраивать
не нужно, а выключенный ноут — не ошибка: скрипт молча выходит с нулём.
Копируется только изменившееся (сравнение по размеру), локальный архив не
чистится никогда — на ноуте `logging.keep_days` удаляет старое через две недели,
здесь оно остаётся навсегда.

**Читать через `Get-Content` по ssh больше не нужно** и не стоит: кириллица
оттуда приходит мусором, если забыть про два ключа кодировки. `scp` копирует
байты и такой проблемы не имеет — на нём скрипт и построен.

**Файлы на ноуте не удалять** — надо удалить, сказать владельцу. Правки только
внутри `D:\Jarvis`, всё остальное — спрашивать.

- Python **3.14.4**, venv в `.venv` (нужен системный пакет `python3.14-venv`).
- Установлено: `PyYAML`, `httpx`, `pytest`, `pytest-asyncio`.
- **Зависимости описаны в `pyproject.toml`** дополнительными наборами. Живому
  запуску нужен один — `full`: `pip install -e ".[full]"`. В него намеренно не
  входят `torch` (его тянут отвергнутые на слух `silero` и `xtts` — два
  гигабайта впустую), сам `xtts` (на процессоре непригоден) и `piper-tts`
  (голоса отвергнуты). А вот `av` входит, хотя пришёл он из набора `edge`:
  без него не читается `activation.mp3`.
  Активацию по имени в `full` даёт `vosk` — он кроссплатформенный, в отличие
  от `openwakeword`, который на Linux требует `tflite-runtime` без колёс под
  Python 3.14. Тот остался в наборе `wakeword` для своей обученной модели.
- Часть необязательных пакетов на сервере всё же стоит (проверялись движки
  синтеза); без них поднимаются заглушки, и система работает.
- Git-доступ по SSH-ключу `/root/.ssh/id_ed25519_github` (прописан в `~/.ssh/config`).
  HTTPS не работает — учётных данных нет.

## Архитектура: решения, которые нельзя откатывать не подумав

Полные обоснования — в `ARCHITECTURE.md`. Здесь суть, чтобы не переделать по кругу.

1. **Два канала связи.** События (`EventBus`) — факты, 1→N, без ответа.
   Команды (`ToolRegistry`) — 1→1, через `await`, с `ToolResult`. Чистый pub/sub
   на запросах вида «какая температура» выродился бы в correlation-id и таймауты
   в каждом скилле. **Скилл никогда не импортирует скилл** — только
   `await self.tools.invoke("имя.инструмента", {...})`.
2. **Роутер отдаёт `Intent` (имя инструмента + аргументы), а не скилл.** Поэтому
   правила и function-calling LLM взаимозаменяемы. Цепочка резолверов:
   `phrase → alias → learned → llm → fallback`. Типовые команды студии до сети не доходят —
   это главная экономия.
3. **`LLMProvider` тонкий: только `complete()`.** Задачи `ask/chat/summarize/
   extract_intent` живут в `LLMService` и написаны один раз. Новый провайдер
   (Gemini, Groq, DeepSeek) = один метод. Профили задач в конфиге дают разные
   модели под разные задачи и смену модели в рантайме (`llm.set_model`).
4. **Whisper и Piper синхронные** — ходят только через `BlockingWorker`. Вызов
   в корутине заморозил бы весь event loop; `async def` сам по себе не спасает.
5. **VAD и wake word** — протоколы с пропускающими заглушками. Без них Whisper
   молотит на любом шуме студии.
6. **Память: два хранилища.** `DocumentStore` (JSON, read-modify-write) для
   `profile/preferences/studio/projects/knowledge`; `JournalStore` (JSONL,
   append-only) для `today/history`. У `ContextBuilder` **нет метода «дай всё»** —
   разделы называются явно, результат режется по бюджету токенов.
7. **`core/contracts/`** — слой, от которого зависят все и который не зависит ни
   от кого. Шов для замены шины, роутера, памяти.
8. **`SkillScope`** — все регистрации скилла (инструменты, подписки, задачи) идут
   через него, выгрузка = `revoke()`. Это же делает возможным `reload`.
   **Подскиллы** (с 30.07.2026): скилл, который не работает без другого, лежит
   внутри него — `skills/browser/page/skill.py`. Это не про красоту каталога:
   `page` зовёт `browser.page_run` и соседом по списку выглядел как вторая
   независимая возможность «для браузера». Вложенность даёт порядок загрузки,
   зависимость (нет главного — подскилл не пробуем) и выгрузку вместе.
   Уровень вложенности **ровно один**. **Имена инструментов от вложенности не
   зависят** — берутся из `meta.name`, `page.pause` остаётся `page.pause`: на
   такие имена ссылается выученное в памяти, а `browser.page.pause` рядом с
   существующим `browser.page_run` читалось бы как одно и то же.
9. **Секреты через `${VAR}` из `.env`**, в коде нет ни путей, ни ключей.
10. **DI через конструкторы**, composition root — `jarvis/core/app.py`. Ни
    глобальных переменных, ни синглтонов.
11. **Режимы (`core/state.py`) и обстановка (`core/situation.py`)** — состояние,
    живущее между командами, и то, что видит модель при разборе. Собираются в
    `app.build` по одному экземпляру на систему и раздаются всем, кому нужны:
    конвейеру, резолверу модели, скиллам (`ctx.modes`, `ctx.situation`).
    Подробности — в разделе «Ум вместо безрукости» ниже.
12. **Второй вход — событие `CommandTyped`.** Команда бывает не только голосом:
    скилл `keys` ловит её с клавиатуры. Но диспетчером, персоной и приглушением
    микрофона владеет голосовой конвейер, поэтому команду со стороны он и
    обрабатывает — тем же `handle`, что и распознанную речь. Скилл шлёт событие,
    конвейер подписан. Так «новый вход не даёт новых прав» выходит буквально
    (текст идёт через тот же роутер), и это готовый шов для входа из Telegram.

## Версии: что именно сейчас запущено (01.08.2026)

Просьба владельца: «сделай систему версий, чтобы по логу можно было понять, на
какой версии ядра и скиллов всё происходит». Логи разбираются на сервере и
через день-другой, и вопрос «это уже с исправлением или ещё до него» решался
гаданием по поведению.

В логе теперь **вторая строка каждого сеанса**:

```
──────── Запуск 01.08.26, 15:31:22 ────────
Jarvis 0.2.0 (fef9cb6, main); Python 3.14.4, Windows 11
...
Скиллы: browser 0.1.0, memory 0.1.0, page 0.1.0, reminders 0.1.0, search 0.2.0, ...
```

- **Отвечает коммит, а не номер версии.** Номер меняется редко, а знать надо,
  какой именно код работал. `jarvis/core/version.py` читает `.git/HEAD` и файл
  ссылки **напрямую**, без запуска `git`: у владельца Jarvis стоит из клона, но
  git в PATH может и не быть, а поднимать процесс на каждом старте ради строки
  расточительно. Свежий клон ссылок на диске не держит — тогда коммит ищется в
  `packed-refs`. Нет `.git` (копия, архив) — просто нет коммита, не ошибка.
- **Версия ядра — в `jarvis/__init__.py`**, оттуда же её берёт `pyproject.toml`
  (дублируется вручную, следить). Поднимать при заметных изменениях: новая
  подсистема, смена контракта. На каждую правку не надо — для этого есть коммит.
- **Версии скиллов одной строкой.** Поштучно они пишутся при загрузке, но
  искать их по десятку строк неудобно, а вопрос задаётся к логу целиком.
- Всё то же есть в `--check` (строки «Версия» и «Среда») и в `core.status`,
  который проговаривает версию вслух: «какая у тебя версия» спрашивают ровно
  тогда, когда сомневаются, что запущено свежее.
- Расширение браузера свою версию сообщало и раньше (`v0.9.1` в `hello`), и
  Jarvis сверяет её с `manifest.json` на диске.

## Голос: как это настроено

```bash
# Всё для живого запуска одной строкой (набор `full` в pyproject.toml):
pip install -e ".[full]"            # плюс dev, если нужны тесты
pip install -e ".[stt,audio,voices]"       # точечно, если нужен один кусок
python -m jarvis --download-voice          # список голосов
python -m jarvis --try-voice ru            # послушать и выбрать
python -m jarvis --devices                 # номера микрофонов и колонок
```

- **Два языка: русский и английский.** Понимает оба, отвечает на языке вопроса.
  Язык определяется для каждой фразы, под него берётся свой голос, реплики
  скиллов существуют в обоих вариантах (`speech={"ru": ..., "en": ...}`).
- **STT: облако Deepgram, местный Whisper — запасной** (07.09.2026). Причина
  измерена: Whisper на этом процессоре работает **медленнее реального времени**
  («распознано 5.3 с речи за 6.5 с», очередь переполнялась, 301 кадр отброшен),
  и это был главный тормоз системы. Модель `nova-3`, при `language: auto`
  просим `multi` — code-switching, иначе второй язык молча отбрасывается.
  Звук уходит **в WAV**: сырой PCM пришлось бы описывать параметрами запроса,
  то есть держать согласованными две записи одного и того же. Язык результата
  определяется **по алфавиту** (`detect_language`), а не по полю ответа — где
  Deepgram его возвращает, в документации не написано.
  **Имя подсказывается словарём** (`stt.keyterms`, 11.09.2026). При
  `language: auto` модель ищет слово сразу в двух языках, и «Джарвис» уходит в
  латиницу: в живом логе он приходил как «Darles», «Harvest», «Чарльз»,
  «Jarda», и роутер получал команду с мусором впереди. Замер на одной фразе:
  без подсказки «Jarvis», с подсказкой «Джарвис». **Отказываться ради этого от
  второго языка не пришлось** — `language: ru` чинит то же самое, но ценой
  английского. Туда же стоит дописывать всё, что произносят и что модель
  коверкает: названия программ, имена в чатах.
  Ключ — `JARVIS_DEEPGRAM_KEY` в `.env`; без ключа система молча работает на
  Whisper. Расход (запросы и секунды звука) виден в «сколько потрачено» рядом
  с токенами.
- **Откат — `FallbackSTT`**: местная модель поднимается **лениво**, при первом
  же отказе облака, и после отказа облако не трогают минуту. Держать Whisper
  загруженным всегда значило бы потерять то, ради чего облако и затевалось:
  полгигабайта и оба ядра. Плата — первая фраза после обрыва, пока модель
  грузится. Обрыв определяется по отказу запроса, а не опросом сети: пинг врёт
  в обе стороны.
- **TTS**: движки за одним интерфейсом (`jarvis/core/tts/backends.py`), выбор
  на каждый язык записью `движок:голос` в `tts.voices`. Доступны `vosk`
  (22 кГц, русский с просодией по BERT, модель 750 МБ), `kokoro` (24 кГц,
  британские мужские), `silero` (48 кГц, нужен torch), `piper` (самый лёгкий),
  `edge` (облако Microsoft), `fish` (облако Fish Audio). Диспетчеризация —
  `CompositeTTS`, загрузка ленивая и кешируется, частоту задаёт сам голос.
  Скорость — одна настройка `length_scale`, каждый движок пересчитывает её
  под себя.
- **Fish Audio — временная замена на время работы над проектом** (07.09.2026).
  Взят не за качество: `vosk:male_1` владельца устраивает. Взят за **время
  запуска** — Vosk поднимает модель на 750 МБ полторы минуты, а за вечер
  правок запусков десятки, и ожидание складывается в часы. Облаку грузить
  нечего. Размен: старт мгновенный, зато ~1.2 с на каждую реплику против долей
  секунды у поднятого Vosk. Закончится работа над голосом — одна строка в
  `tts.voices`, и всё возвращается.
  Модель называется **заголовком** запроса, а не полем тела (их же
  предупреждение). Работаем на `s2.1-pro-free`: платные требуют отдельного
  API-кредита, который считается не тем же счётом, что кредит платформы, и без
  пополнения отвечают 402. Новых зависимостей не тянет — только `httpx`,
  который и так основной.
- **Запасной голос — `tts.fallback: kokoro:bm_george`** (07.09.2026). С
  облачным синтезом это условие работоспособности, а не роскошь: без сети
  ассистент иначе немеет целиком и не может даже сказать, что случилось.
  Kokoro взят потому, что местный и лёгкий — грузится секунды, а не полторы
  минуты. Русскую реплику он читает по-английски: язык при синтезе берётся от
  **голоса**, и `normalize_for_speech` переводит кириллицу латиницей — с
  акцентом, но разборчиво. После отказа основной голос не трогают минуту, иначе
  каждая реплика начиналась бы с ожидания таймаута. **Старт при мёртвом облаке
  теперь не падает**, пока есть запасной: не запустившийся ассистент хуже
  ассистента с плохим голосом. Запасной обязан быть среди `voices` — иначе он
  не загрузится и в нужный момент окажется так же недоступен.
- **VAD**: по умолчанию **Silero** (`audio.vad.engine: silero`), энергетический
  запасной. Причина — музыка: энергетический меряет громкость и пускает фон в
  Whisper целиком, Silero отвечает на другой вопрос — речь ли это. Модель 2 МБ
  качается сама. Нет модели, сети или onnxruntime — предупреждение и откат.
- **Активация по имени: два способа сразу, и это не дубль.** По тексту
  (`mode: text`) — дёшево, фраза всё равно расшифровывается. По звуку
  (`mode: acoustic`) — до распознавания; только так успеваем приглушить музыку
  раньше команды. **Включено с 04.09.2026**, движок `vosk`: обычное
  распознавание со словарём из одного слова. Обучать нечего, модель русская и
  качается сама (45 МБ), поднимается за 0.7 с, считает в 30–60 раз быстрее
  реального времени, имя опознаётся к 0.7 с. Не поднялось — молча откат на
  `text`. Подробности и замеры — `docs/wakeword.md`.
- После голого «Джарвис» открывается окно `follow_up_s` (10 с), в котором
  команда принимается без имени.

Подробности по каждому движку, наборы для прослушивания, установочные тонкости
XTTS и грабли (в том числе «Silero VAD требует контекст, и молчит об этом») —
в `docs/lessons.md`, раздел «Голос: настройка целиком».

**Второй вечер, после выключения эхоподавления.** Распознавание чинить больше не
пришлось — все фразы разобрались целиком (разбор в `docs/lessons.md`). Осталось
три находки, и ни одна не про звук:

- **Ассистент не умел разговаривать.** Подсказка свободного разговора объявляла
  весь канал «тем, что не удалось выполнить командой», и модель отвечала «не
  понял команду» даже на «как дела». Разговор теперь назван работой, а отказ
  оговорён отдельным условием.
- **Имя двоится в расшифровке, хотя сказано один раз.** «Джарвис, как дела»
  приходило как «Джарвис Прарвисская дела»: на коротком плохо расслышанном
  обращении Deepgram выдаёт подряд две догадки об одном слове. Снималась одна,
  вторая шла в роутер мусором. Теперь снимаются обе — порог отдельный и ниже
  основного, выбран замером.
- **«Открой браузер» подсвечивало кнопку на панели задач** вместо браузера, а
  сама команда срывалась по таймауту. Две разные причины, обе описаны выше в
  разделах про `browser` и `windows`.

**Сколько стоит непрерывная работа** (замерено, не прикинуто):

| звено | доля одного ядра |
|---|---|
| Имя (vosk), на каждом кадре | 5.0% |
| Петлевой захват для эхоподавления | 3.1% |
| Детектор речи (silero) | 1.6% |
| Эхоподавление | 0.7% |
| Детектор речи (energy), для сравнения | 0.1% |
| **Вместе** | **10.4%** |

Половину греет модель имени: она декодирует **каждый** кадр, включая тишину.
Очевидный рычаг — декодировать только под речь, благо детектор речи стоит втрое
дешевле. Не сделано намеренно: имя произносят первым, детектор узнаёт о речи с
опозданием, и без буфера предыдущих кадров начало слова потеряется. Ломать
работающую активацию ради четырёх процентов вслепую нельзя.

**Поэтому замер переехал внутрь** (`jarvis/core/meter.py`, 11.09.2026): теперь
звенья считаются в живом запуске, а не на стенде. Раз в минуту в лог уходит
строка вида «Нагрузка: всего 11.2% ядра (имя 5.1%, петля 3.0%, речь 1.6%,
эхо 0.7%, прочее 0.8%)», и то же спрашивается голосом — «сколько ты ешь»
(`core.load`).

- **Меряется время потока, а не процесса.** Петлевой захват живёт отдельным
  потоком, и без такого разделения он приписывался бы голосовому кругу.
- **Ожидание в счёт не идёт**: звено, которое ждёт сеть, ноутбук не греет.
  Поэтому размечены только синхронные куски; у распознавания и синтеза замер по
  своему потоку врал бы, там работа уходит в `BlockingWorker`.
- **Остаток виден отдельно** («прочее»): цикл событий, разбор JSON, сам Python.
  Подгонять его к нулю незачем, важно знать, что он есть.
- Сам счётчик почти бесплатен: два обращения к часам на кадр. Выключается
  `runtime.meter`.

## Манера речи

`jarvis/core/persona.py` — единственное место, где решается, как ассистент
звучит. Шесть ситуаций: `listening`, `working`, `done`, `failed`, `greeting`,
`farewell`; у каждой набор вариантов на русском и английском, подряд один и тот
же не повторяется. Владелец просил манеру из фильма — отсюда «сэр» и сдержанный
тон.

- **`working` — речь по ходу дела** (11.09.2026). Затянувшаяся команда через
  `audio.working_after_s` (2.5 с) отзывается «секунду» и продолжает работать.
  Это не вежливость: молчащий несколько секунд ассистент неотличим от
  зависшего, человек повторяет команду, и повтор **выполняется вторым разом**.
  Порог высокий намеренно — заполнитель занимает голос, а голос один, поэтому
  настоящий ответ подождёт, пока он договорит. Команды из шаблонов до порога не
  доживают. Заполнитель не попадает в `last_reply`: `--say` печатает результат,
  а не «секунду».

- **Свои слова команды тоже варьируются, и выбирает их персона** (`choose`).
  `ToolResult.speech` принимает набор: `{"ru": ("Пауза.", "Остановил."), ...}`.
  Разделение не формальное: **что** сказать знает скилл, а «не повторяться и
  помнить, что уже сказал» — одна забота на всю систему. `speech_for()`
  возвращает первый вариант — для текстового ввода и тестов, где персоны нет и
  нужна предсказуемость.
- **Обращение — поле `{address}`, а не текст фразы**: меняется одной строкой
  `persona.address`, в том числе на пустую.
- **Тот же характер уходит в системную подсказку `core.chat`**
  (`Persona.style`), иначе ассистент отзывается как Джарвис, а разговаривает
  как чат-бот. Это ~40 токенов и только в задаче `dialog`.
- **Приветствие и прощание живут в `JarvisApp.run`**, а не в `pipeline.start`:
  это свойство живого сеанса, `--check` и `--say` молчат.

Ограничения на текст реплик (алфавит движка, латиница, опечатки в названиях
ситуаций, объяснение ошибки вместо вежливого отказа) — в `docs/lessons.md`,
раздел «Манера речи».

## Эхоподавление (AEC): сделано 01.08.2026

Просьба владельца: «на большой громкости Джарвис вообще не откликается».
Приглушение музыки эту дыру не закрывает — оно случается **после** того, как
ассистента позвали, а само слово «Джарвис» произносится в полный фон. AEC
работает всегда и знает вычитаемое сэмпл в сэмпл: копия того, что уходит на
колонки, снимается прямо из системы.

Где лежит: `jarvis/core/audio/aec.py` (математика), `loopback.py` (захват),
`echo.py` (стыковка потоков и обёртка над микрофоном), `checkup.py` (команда
`--check-aec`). Настройки — `audio.aec` в конфиге, пакет —
`pip install -e ".[aec]"`.

**Что намерено сделано своими руками, а не взято готовым.** Сборок WebRTC APM и
speexdsp под Windows и Python 3.14 нет; собирать их у владельца — отдельная
беда. Фильтр же оказался дешёвым: блочный частотный NLMS с разбиением на
разделы живёт одним массивом `(разделов, бинов)`, и весь расчёт — пара БПФ на
блок в 16 мс. Зависимостей ноль, numpy и так стоит ради Silero.

**Измерено на стенде** (настоящая речь плюс синтетическое эхо, тесты в
`tests/test_audio_aec.py` меряют децибелы, а не «работает/не работает»):
речь была на 20 дБ тише музыки, стала на 4 дБ громче — **выигрыш 24 дБ** на
линейном тракте. С искажениями колонки меньше: перегрузка вдвое — 15 дБ,
втрое — 11, впятеро — 6, ввосьмеро — 3.5. То есть на очень большой громкости
отдача падает, но в минус не уходит никогда. Стенд, однако, не живая машина:
комната, колонка с сабом и микрофон в корпусе ноутбука есть только у владельца,
для того и сделана `--check-aec`.

**ВЫКЛЮЧЕНО 11.09.2026: на живой машине фильтр портил сигнал.** Лог двух
сеансов подряд: «убрано **-4.4 дБ**, потеряно опоры 183040 сэмплов, пересборок
5» и «убрано **-4.7 дБ**, потеряно опоры 394354, пересборок 10». Минус — значит
не вычитал эхо, а добавлял искажений. Один раз выравнивание придержало микрофон
на **707 мс**.

Беда не в том, что эхо остаётся, а в том, что через фильтр проходит **весь**
звук, идущий в распознавание, и портится он всегда — даже когда музыки нет.
Владелец жаловался ровно на это: «оно вообще само по себе плохо распознаёт».

Приглушение музыки (`skills.settings.windows`) работает и остаётся: двадцать с
лишним децибел мгновенно и без обработки сигнала. Включать AEC обратно — когда
разъезд потоков будет починен и `--check-aec` покажет плюс, а не минус.

**Подтверждено живым запуском в тот же вечер.** Два сеанса подряд, одна и та же
комната, одна и та же модель; разница только в этой строке конфига. С фильтром:
«Покаокаокаока», «Дарвис, blue cheese», «Такимой softestenей». Без фильтра все
четыре фразы разобраны целиком, имя написано верно каждый раз. То есть ни
расстояние до микрофона, ни шум, ни `nova-3` виноваты не были.

**Прежний замер 07.09.2026 был положительным: убрано 17 дБ.**
Восемь окон подряд за сорок секунд дали сдвиг −250.7…−250.0 мс, то есть
**разброс в одну миллисекунду**: дрейф 0.001% (10 ppm) — обычная кварцевая
погрешность. Потоки идут в такт, фильтру ничто не мешает.

Прежний вывод («расхождение 1.86%, эхоподавление работать не может») **был
неверен, и виноват в нём был сам замер**. Считался он делением числа сэмплов на
время по часам и выдал «микрофон 16277 Гц» при номинале 16000 — плюс 1.7%,
столько не врёт ни один кварц. Делились разъехавшиеся моменты старта и
остановки двух потоков, а не частоты. Кривая методика (`_tell_rates`) удалена
07.09.2026; дрейф меряет `_note_drift` — по тому, как уползает сдвиг, в ppm, —
и `--check-aec`, который теперь режет запись на окна и показывает наклон.

**Мерить дрейф надо по нескольким окнам и брать медиану приращений.** Первая же
версия проверки провела прямую через все точки и по одному выбросу среди пяти
объявила дрейф +15 мс/с, которого не было. Один разрыв в потоке утаскивает
прямую целиком.

Что до условий: копия снимается напрямую с «Динамики (JBL Flip 6)», хотя в
системе стоит и Voicemeeter со своим тактовым генератором. Похоже, 28.08 звук
шёл через него — на виртуальном устройстве дрейф вполне мог быть настоящим.

## Зрение: скилл `screen`, сделано 11.09.2026

Разбор с владельцем: «в фильме у Джарвиса руки развязаны, а наш умеет только

Где лежит: `skills/screen/skill.py`. Инструментов два, в каталог модели идёт

отладка и будущий агентный цикл, которому надо посмотреть на результат
собственного действия.

**Новых зависимостей не добавилось.** Pillow умеет снимать экран сам
(`ImageGrab.grab`), а прямоугольник окна и монитора берётся через ctypes тем же
приёмом, каким `windows` перечисляет окна. Объявлен набор `vision` в
`pyproject.toml`, `pillow` вошёл и в `full`.

**В ядре изменилось ровно одно**: у `Message` появилось необязательное поле
`images`, и составной вид `content` собирается **только когда картинки есть**.
Текстовый запрос уходит на провод байт в байт таким же, как до зрения, и это
закреплено тестом. Причина простая: составной вид проверен у нас только на
зрении, а текстовых запросов система делает тысячи.

**Сжатие снимка оказалось страховкой, а не экономией** — ровно наоборот тому, с
чего скилл начинался. Замер на `gemini-2.5-flash` показал, что цена картинки
растёт **ступенями**, и на всём участке от 768 до 2200 пикселей она не меняется
вовсе:

| длинная сторона | 256 | 512 | 768…2200 | 2400 | 3200 |
|---|---|---|---|---|---|
| входных токенов | 331 | 1363 | **1879** | 2395 | 3427 |

Зато читаемость от сжатия портится всерьёз: тот же снимок, ужатый до 768, дал
**уверенно неверный** ответ — «KeyError: 'ru'» вместо «'de'». Это худший исход из
возможных, потому что это не отказ, который слышно, а ошибка, неотличимая от
правды. Отсюда предел в родную ширину экрана (1920): обычный снимок не
пересчитывается вовсе. Заодно он и легче — 336 КБ против 645 у ужатого до 1600,
потому что ресемплинг размывает резкие края, а PNG сжимает их хуже.

**Осведомлённость о масштабе объявляется при загрузке скилла**
(`claim_dpi_awareness`). Без этого Windows врёт масштабированному процессу:
`GetWindowRect` вернёт логические координаты, а снимок делается в физических, и
на экране со 150% вырезался бы не тот кусок.

**Правило приватности, и оно не формальность.** Снимок уходит в чужое облако, а
на экране бывает переписка, открытый пароль, ключ в терминале. Поэтому: снимок
делается **только по прямой команде**, никогда сам и никогда в фоне, нигде не
сохраняется и живёт в памяти ровно на время запроса. Факт отправки пишется в лог
вместе с размером и вопросом. Фоновое наблюдение за экраном — отдельный
разговор, который без решения владельца не начинается.

Профиль задачи свой — `vision` в `llm.profiles`: модель обязана уметь картинки,
а разбор команд идёт на самой дешёвой. Нет профиля — скилл честно докладывает об
этом в `health`, а не падает.

**Разные мониторы** (11.09.2026). «Что на втором мониторе» раньше снимало тот
экран, где активное окно: номер терялся по дороге, модель звала инструмент без
него. Теперь номер разбирается и цифрой, и словом («2-ом», «втором»), а мониторы
перечисляются **слева направо** — человек считает их глазами, а системный порядок
зависит от того, в каком гнезде кабель. Номера нет в наличии — ассистент честно
говорит, сколько мониторов есть, вместо того чтобы молча показать не тот:
первое поправят, второго не заметят. Фразы про мониторы разбираются шаблонами,
то есть бесплатно, без обращения к модели.

Проверено сквозным запуском: синтетический снимок терминала, вопрос «какая
ошибка», ответ «KeyError: 'de'» за 2.15 с. На живом экране проверен захват
(1920×1200, 336 КБ, 0.29 с); **связка с микрофоном владельцем ещё не
прогонялась**.

## Ум вместо безрукости: режимы, обстановка, часы (01.08.2026)

Разбор с владельцем: «скажу „в течение следующих 30 минут не слушай“ — он не
поймёт либо сделает совсем не то». **Вывод разбора: он не глупый, он
безрукий** — в этой фразе нечего понимать, любая модель разберёт её с первого
раза. Не хватало органов: часов, состояния, глаз и возможности сказать больше
одного вызова. Три из четырёх сделаны.

**Режимы — `jarvis/core/state.py`.** Флаг с именем и сроком жизни; готовых два:
`deaf` («не слушаю») и `brief` («отвечаю коротко»). Инструменты `core.sleep`,
`core.be_brief`, `core.as_usual`, `core.modes`. Планировщик тут не нужен: режим
читают на каждой реплике, отсюда ленивое истечение — ни тика, ни фоновой
задачи. Перезапуск режимы не переживают намеренно. Гейт «не слушаю» стоит **в
конвейере, а не в инструменте**: остановленная там реплика не стоит ни ожидания,
ни токена. Из режима обязан быть выход — гейт пропускает обращение по имени плюс
фразы из `WAKE_PHRASES`, и этот список **один на двоих** с `core.as_usual`
(сверяется тестом).

**Обстановка — `jarvis/core/situation.py`.** Две-три фразы в системную подсказку
разбора: время, включённые режимы, факты о происходящем, прошлая команда.
Выключатель — `router.situation`. Сюда попадает **только то, что уже под
рукой**: факты приносят те, кто узнал их по дороге (`ctx.situation.note`), а не
собираются опросом — иначе к каждой команде добавился бы круг ожидания. У факта
обязателен срок годности: устаревший хуже, чем никакой.

**Часы — скилл `reminders`.** «Напомни через час», «в 18:30», «поставь таймер
на 10 минут». Скилл, а не ядро: фоновая задача, хранилище и вызов по имени у
скиллов уже есть. Срок хранится в стенных часах — напоминание обязано пережить
перезапуск. Время разбирается кодом (`parse_when`), а не моделью; не разобрали —
переспрашиваем, а не ставим наугад.

**Ассистент, заговоривший без вопроса.** Сработавшее напоминание — первая
реплика без спрашивающего. Скилл не ходит в синтез напрямую: публикует
`AnnouncementRequested`, произносит голосовой конвейер — только он глушит
микрофон на время речи, иначе ассистент услышит сам себя и выполнит собственное
напоминание как команду. `_say` под замком: две реплики иначе полезли бы в
динамик разом. Это же будущий шов для инициативы, но пользоваться им в ту
сторону — сильно потом.

**Цепочки через союз «и» — сделано 08.09.2026** (`Dispatcher._chain`).
«Сделай громче и поставь на паузу» — две команды в одной фразе. Правило «план
не даёт новых прав» соблюдено буквально: каждая половина идёт через тот же
роутер, то есть это ровно то же, что сказать две команды подряд.

Главное тут — **не разрезать лишнего**: союз живёт и внутри команд («включи
трек Я сошла с ума и не помню», «напиши маме буду через час и куплю хлеб»).
Поэтому режем, **только если каждая половина опознана как команда**, а
`fallback` при проверке не спрашивают — он согласился бы на что угодно, отправив
хвост названия в свободный разговор. Модель при проверке тоже не спрашивают:
гипотеза подтверждается не всегда, и платить за каждую догадку значило бы
сделать союз дороже, чем он стоит. Отсюда честное ограничение — цепочка
работает для команд из шаблонов и выученного; незнакомая формулировка идёт
целиком, как раньше. Сорвалась первая команда — вторую не делаем: человек
подразумевает порядок, а не два независимых поручения.

**Обратимость объявлена у каждого инструмента** (11.09.2026,
`@tool(reversible=...)`). Правило «план не даёт новых прав» до этого соблюдать
было нечем: система не отличала «сделать громче» от «отправить маме сообщение».
Теперь у `ToolSpec` три состояния — `True`, `False` и `None` («автор не
объявил»), а свойство `unattended` отвечает утвердительно **только на явное
`True`**. Молчание трактуется в пользу вопроса: забытый `routable` стоит денег,
забытый `reversible` — отправленного не тому человеку сообщения.

**На прямую команду голосом флаг не влияет вообще.** Сказал «закрой браузер» —
сам и разрешил. Флаг нужен там, где шаг выбрал план.

Сейчас необратимыми помечен 21 инструмент из 74: отправка в Telegram, закрытие
и убийство программ, блокировка компьютера, закрытие вкладок, запись в память,
отмена напоминания, лайки и нажатия на странице, произвольный шаг `page_run` и
`page.control`, а также **оба инструмента зрения** — снимок экрана уходит в
чужое облако, и «только по прямой команде» означает, что шаг, выбранный планом,
прямой командой не является. Непомеченных нет, и это держит тест
`test_every_tool_in_the_project_declares_reversibility`: он читает исходники
через `ast`, а не поднятую систему, потому что часть скиллов только под Windows
и на Linux в проверку бы не попала.

**Агентный цикл — сделан 11.09.2026**, `jarvis/core/agent.py`, инструмент
`core.plan`. До него `Dispatcher.handle` делал ровно один вызов и на этом
заканчивался; цепочка через союз «и» циклом не была, потому что обе команды
называл человек. Здесь другое: **модель видит результат своего шага и решает
следующий по нему**. «Узнай погоду в Твери и в Москве и скажи, где теплее» —
два вызова и ответ по их итогам.

- **Место — ядро, а не скилл**, хотя правило проекта велит сомневаться. Цикл не
  добавляет возможностей: он не умеет ничего, чего нет в реестре. Он меняет то,
  **как** выполняется уже существующее, — как роутер и диспетчер.
- **Вход через обычную маршрутизацию.** `core.plan` — такой же инструмент в
  каталоге, и выбирает его модель, когда просьба составная. Отдельного пути
  внутри диспетчера нет, и знакомые команды по-прежнему идут шаблонами даром.
- **«План не даёт новых прав» соблюдается буквально.** Каждый шаг идёт через тот
  же реестр, что и голосовая команда, а **необратимый шаг не выполняется
  вовсе**: цикл останавливается и говорит, обо что упёрся. Подтверждения голосом
  пока нет намеренно — диалог согласия требует состояния между репликами, а
  отказ не требует ничего и не может ошибиться в опасную сторону. Владелец,
  услышав отказ, говорит ту же команду напрямую: на прямую команду пометка
  обратимости не влияет.
- **Четыре предохранителя, и каждый закрыт тестом**: предел шагов
  (`MAX_STEPS = 5`), остановка на повторе того же шага с теми же аргументами,
  остановка после сорвавшегося шага (как в цепочке через союз: человек
  подразумевает порядок), и `HIDDEN` — цикл не видит `core.plan` и `core.chat`.
  Первый дал бы план внутри плана, второй «выполнял» бы цель разговором о ней:
  свободный разговор отвечает всегда, и любая недостижимая цель выглядела бы
  успешной.
- **Формат переписки нарочно простой.** Родной tool-calling требует хранить в
  сообщениях и вызов, и ответ на него с идентификатором — это расширило бы
  контракт `Message` ради одного места. Вместо этого после каждого шага уходит
  обычная реплика «вызвал то-то, получилось то-то». Модели хватает, а
  `LLMProvider` остаётся тонким.
- **Замер живьём**: план из двух шагов — 4.3 с, три запроса, 4815 токенов,
  $0.0015. Заполнитель «секунду» на таком плане срабатывает, для того и делался.

**Долгая работа уходит в фон — сделано 11.09.2026**, `jarvis/core/jobs.py`,
инструменты `core.later` и `core.jobs`. Пока работа шла внутри реплики, человек
ждал ровно столько, сколько она идёт; для секунд это лечится заполнителем
«секунду», для минут не лечится ничем. Теперь поручение принимается, ассистент
отвечает «займусь и доложу» и **заговаривает сам**, когда закончит, — тем же
швом, которым говорят напоминания.

- **Доклад приходит всегда**: и на удачу, и на неудачу, и на падение с
  исключением. Молча потерянное поручение хуже невыполненного — на него уже
  понадеялись.
- **Мест три.** У каждого дела свой доклад вслух, и пятеро закончивших разом
  устроят монолог на полминуты. Отказ возвращается значением, а не исключением:
  иначе каждый вызывающий писал бы один и тот же `try`.
- **Перезапуск задачи не переживают**, и обещать обратное нельзя: возобновить
  наполовину выполненный план, не зная, что из него уже случилось, невозможно.
- Замер живьём: ответ «займусь» за 0.00 с, доклад о погоде через 3.8 с.
- `core.later` спрятан от агентного цикла (`HIDDEN`) вместе с `core.plan`:
  поручение запускает такой же цикл, и план, раздающий поручения себе,
  размножился бы в стороне от всякого предела шагов.

**Переспрашивание — сделано 11.09.2026**, `jarvis/core/pending.py`. Цикл, дойдя
до необратимого шага, теперь не отказывается, а **спрашивает**, и ответ владельца
и есть разрешение: подтверждённый шаг идёт тем же путём, что и та же команда,
сказанная вслух сразу. Правило «план не даёт новых прав» от этого не страдает —
права даёт голос человека, а не план.

- **Единственное состояние между репликами во всей системе**, и живёт оно в
  диспетчере: он один пропускает через себя **каждую** реплику, откуда бы она ни
  пришла. У вопроса есть срок годности (90 с) — «да», сказанное через час по
  другому поводу, не должно исполнять забытое.
- **Вопрос снимается любой следующей репликой**, даже если она не ответ. Висящий
  вопрос опаснее забытого.
- **Разбор ответа строгий и с перекосом в сторону отказа**: отрицание где угодно
  в короткой реплике читается как «нет», а согласием считается только реплика,
  все слова которой из списка согласия. «Конечно нет» — отказ, «да, но сначала» —
  вообще не ответ. Лишняя отмена стоит одного повторения, лишняя отправка —
  сообщения не тому человеку.
- **Вопрос открывает широкое окно ответа** (`_await_answer` в конвейере): на
  «отправить маме?» отвечают, не называя имени заново, иначе переспрашивание
  выходит неудобнее, чем повторить команду.
- **Вопрос формулируется описанием из каталога**, а не именем инструмента:
  «memory.remember» на слух не значит ничего, а «записать факт в журнал» значит.
  Значения аргументов в вопрос идут, их названия — нет.
- Замер живьём: план дошёл до записи в память, спросил «дальше нужно записать
  факт в журнал: в Твери сейчас 15 градусов… Делать?», на «да» записал ровно это.
  Роутер выбирает `core.plan` сам на составных просьбах — проверено на двух.

В фоновом поручении (`core.later`) вопрос не задаётся намеренно: человек занят
другим, и на вопрос, прозвучавший через пять минут, отвечать не готов. Фоновая
задача докладывает, обо что упёрлась, и ждёт прямой команды.

## Скиллы, которые ассистент пишет себе сам (11.09.2026)

Последний из четырёх недостающих органов. Скилл `author`, инструменты
`author.learn`, `author.accept`, `author.drafts`.

Круг целиком: «научись показывать, сколько работает компьютер» → ассистент
отвечает «займусь, доложу» → через минуту докладывает, что скилл написан и
проверки прошёл → владелец читает файл → «прими скилл uptime» → модуль
подключается **на ходу**, и он же сразу отвечает на «сколько работает
компьютер». Проверено целиком 11.09.2026, каталог вырос с 80 инструментов до 81
без перезапуска.

- **Пишет агент-кодер из панели**, а не модель из `llm.profiles`: ему нужно
  читать, писать и проверять файлы. Замер: 57 с на скилл вместе с проверками.
- **Готовое само не включается.** Файл ложится в `drafts/`, куда автозагрузка не
  смотрит, — то есть он не подключится даже после перезапуска. Владелец читает и
  принимает отдельной командой. Код, написанный в облаке, не должен начинать
  работать на живой машине оттого, что кто-то не глядя сказал «да».
- **Написанное проверяется ruff и mypy до доклада**, и это не придирка. На
  первом же живом запуске агент написал `HealthStatus.unhealthy` (такого метода
  у нас нет) и обратился к часам, которых нет на Windows. Код выглядел
  безупречно, линтер молчал, **обе ошибки нашёл mypy за секунду**. Не прошло —
  одна попытка исправления, и об исходе говорится вслух первым делом.
- **После машинных проверок написанное смотрит свежий агент** (11.09.2026,
  `review`, выключается в настройках скилла). Линтер и типы ловят опечатки и
  несуществующие имена; они не поймают неверную пометку обратимости, реплику,
  которую нельзя произнести, или проглоченный сбой. Смотрит **отдельная
  сессия**: спрашивать автора, хорошо ли он написал, бессмысленно.

  Спрашивается не «хорошо ли», а закрытый список того, что тут уже ломалось, и
  даётся ответ «ЧИСТО» — без него замечания находятся всегда, из вежливости.
  Замечания ложатся рядом с черновиком в `review.md`, вслух не зачитываются.

  На первом же запуске разбор нашёл в скилле уборки загрузок три вещи, из них
  одну настоящую: сбой доступа к каталогу глушился и выдавался за «удалять
  нечего». Ни линтер, ни mypy такого не видят. Плата — около полуминуты: скилл
  стал занимать 106 с вместо 57.
- **Имя скилла становится путём на диске**, поэтому проверяется белым списком
  (`safe_name`), а не чёрным: перечислить все способы выйти из каталога нельзя.
- **Соглашения проекта едут в запросе целиком**: агент работает в пустом
  каталоге и нашего кода не видит. Там же копятся готовые ответы на пойманные
  противоречия — например, к Windows API обращаться через `ctypes.WinDLL`, а не
  через `ctypes.windll`: первого не знает mypy на Linux-стабах, а обход через
  `getattr` не нравится ruff. Без этой строки скилл не проходил проверки и со
  второго раза.
- `core.reload_skill` теперь умеет **подключать новое**, а не только
  перезагружать загруженное (`SkillManager.adopt`). Это и есть то, что
  превращает «файл написан» в «умение появилось».

Осталось на потом: путь через пулл-реквест. Он лучше — обзор в вебе, история,
откат, — но требует токена GitHub, которого на 11.09.2026 нет ни в `.env`, ни у
пользователя панели. Черновик даёт ту же защиту и работает уже сегодня.

## Речь без вопроса: `jarvis/core/attention.py` (11.09.2026)

Ассистент, который замечает и сообщает сам, — это то, чего не хватало больше
всего: до сих пор он существовал ровно те секунды, пока к нему обращались. Но у
этой способности **ровно одна настоящая опасность, и она не техническая**:
ассистента, который дёргает по пустякам, выключают через день. Поэтому политика
«когда говорить» живёт одним местом на всю систему, отдельно от тех, кому есть
что сказать.

Правило разделения: **источник знает, что случилось; уместность знает
`Announcer`.** Скилл не имеет о ней своего суждения и не должен — иначе каждый
источник новостей заведёт своё, и они разъедутся.

- **Три важности**, и разница в том, что будет, если промолчать. `LOW` — не
  узнает ничего страшного («тебе написали»); `NORMAL` — не узнает результат
  того, что сам поручил; `URGENT` — не узнает того, о чём просил сообщить.
- **Заблокированное придерживается, а не выбрасывается**, и досказывается при
  следующем разговоре: человек, сам обратившийся к ассистенту, заведомо
  слушает. Потерять доклад о поручении нельзя — его ждали.
- **Что придерживает**: режим «не слушаю» (говорить в ответ на просьбу не
  отвлекать — худшее из возможного), время тишины из конфига, пауза между
  репликами и выключатель `attention.enabled`. Повтор того же текста —
  единственное, что именно **выбрасывается**: придержать его значило бы
  произнести дважды.
- **Напоминания сюда не идут, и это не упущение.** Политика — про речь, о
  которой не просили; напоминание просили буквально, и придерживать его значило
  бы нарушить обещание, ради которого его и заводили.
- **Первый наблюдатель — Telegram.** Событие о входящем скилл публиковал и
  раньше, но его никто не слушал. Теперь при `skills.settings.telegram.announce`
  скилл предлагает реплику политике. Отдельно от `notify`: событие в шине никому
  не мешает, а речь без вопроса мешает очень. По умолчанию выключено.
- Вслух идёт кто написал и **начало** сообщения: это уведомление, а не чтение
  переписки — для чтения есть «прочитай, что пишет мама».

Полный разбор с обоснованием каждого решения — в `docs/lessons.md`, раздел
«Режимы, обстановка и часы».

## Токены: где они уходят

Владелец платит за OpenRouter, поэтому расход — проектное ограничение, а не
мелочь. Порядок величин важнее конкретной модели.

**Замер от 04.09.2026** (в прежней редакции стояло: 22 инструмента, ~2400
токенов на фразу):

| | |
|---|---|
| Инструментов всего | 83 |
| Уходит в модель (`routable`) | 51 |
| Каталог в function-calling | 15 235 символов JSON |
| **Каталог в токенах, замерено** | **1466** |
| Фраз мимо модели | 480 |

**Прежняя оценка «4–5 тысяч токенов» была втрое завышена** (исправлено
11.09.2026). Считалась она делением символов на три — привычное правило для
обычного текста, но схемы инструментов не обычный текст: `"type": "function"`,
`"properties"`, `"type": "string"` повторяются десятками, и токенизатор жмёт их
до **10.4 символа на токен**. Тот же род ошибки, что и с частотой микрофона в
разделе про эхоподавление: правдоподобная арифметика вместо измерения.

Считать надо **настоящим запросом**, а не по символам. Разница между запросом с
каталогом и без него — это и есть цена каталога:

```python
from jarvis.core.app import JarvisApp
from jarvis.core.config import load_config
from jarvis.core.llm import Message
app = JarvisApp.build(load_config())
await app.start(ears=False, voice=False)
schemas = app.registry.catalog().function_schemas()
bare = await app.llm.complete([Message.user(".")], task="intent", max_tokens=4)
full = await app.llm.complete([Message.user(".")], task="intent", tools=schemas, max_tokens=4)
full.usage["prompt_tokens"] - bare.usage["prompt_tokens"]
```

Порядок величин из этого другой, и он важен: один инструмент в каталоге стоит в
среднем **около 35 токенов**, а не полутора сотен. Каталог всё равно остаётся
главной статьёй расхода, потому что платится на каждой неузнанной фразе, но
запас до неприятного больше, чем считалось.

- **Главный расход — задача `intent`.** Она срабатывает на каждой фразе, не
  узнанной `phrase` и `alias`, и тащит с собой весь каталог. Сам вопрос при
  этом весит 20 токенов: **99% платы — за каталог**.
- **Поэтому лучшая экономия — не звать модель.** Фраза, добавленная в `phrases`
  скилла, обрабатывается бесплатно и мгновенно; сейчас так закрыто 419 фраз.
  `LLMResolver` пишет в лог каждую фразу, которую пришлось разбирать моделью, —
  это готовый список кандидатов в `phrases`.
- **Удачные разборы копятся сами** (резолвер `learned`): одна и та же
  формулировка платит модели один раз в жизни, а не каждый раз. Живая речь
  однообразна — «заблокируй ноутбук» говорится одними словами месяцами.
  Память при этом **сверяется с реестром** (08.09.2026): выученное на удалённый
  скилл иначе отвечает «не понял команду» и не пускает фразу к модели вовсе —
  так «включи видео …» было сломано полтора месяца после удаления `youtube`.
  Мёртвые записи выносятся при старте, а рост ограничен `LEARNED_LIMIT` с
  вытеснением по пользе: без предела память копила ошибки распознавания
  («как варить порч» и «как варить порчи» — две записи об одном).
- **Служебные инструменты в каталог не попадают** (`@tool(routable=False)`) —
  сейчас таких 31 из 72: `core.reload_skill`, `core.set_model`, `core.as_usual`,
  `core.modes` и почти весь `page`. Голосом их не зовут (а `as_usual` до модели
  и не доходит — гейт «не слушаю» сверяет фразы буквально), а вес они имели.
  Это единственный рычаг, которым каталог держат: новый
  инструмент, который голосом не зовут, обязан помечаться сразу, иначе он
  оплачивается в каждом запросе до конца жизни проекта.
- **Отказ дешёвой модели стоит дороже, чем вторая попытка.** Дешёвая ошибается
  в одну сторону: видит каталог и всё равно отвечает текстом — деньги
  потрачены, команда не выполнена, худший из исходов. Поэтому
  `router.intent_tasks` — список `[intent, intent_strong]`, и вторая модель
  спрашивается **только при отказе первой**, то есть платим лишь за неудачные
  разборы. Цена ошибки в другую сторону: обычный вопрос («как дела») тоже
  получит вторую попытку, и это ~$0.0004 сверху; не устраивает — оставить одну
  задачу в списке. Опечатка в названии задачи ловится при сборке
  (`_intent_tasks` в `app.py`), а не в рантайме.
- **Режимы стоят двух инструментов в каталоге** (`core.sleep`, `core.be_brief`,
  01.08.2026) — около 70 токенов на каждой неузнанной фразе. Это осознанная
  плата за целый класс просьб; их выключатели `core.as_usual` и `core.modes` в
  каталог не пошли, поэтому вышло два, а не четыре. Обстановка — несколько
  десятков токенов сверху (`router.situation`, выключается одной строкой).
- **Выход дороже входа в 4–10 раз**, поэтому `max_tokens` урезаны до 200–300:
  реплику всё равно произносят вслух, длинную никто не дослушает.
- **Расход считается сам.** `LLMService.spending` копит запросы, токены и
  стоимость; OpenRouter возвращает цену в долларах, если послать
  `usage: {include: true}` — свой прайс-лист в коде держать не нужно. Итог
  пишется в лог после каждого запроса и доступен по команде «сколько потрачено»
  (`core.spending`).
- **Идентификаторы моделей у OpenRouter неочевидны**: в конфиге стоял
  `anthropic/claude-haiku-4-5`, а в каталоге он называется `claude-haiku-4.5` —
  через точку. Сверяться с `https://openrouter.ai/api/v1/models` (открыт без
  ключа, там же цены и поле `supported_parameters`, где видно поддержку
  `tools`).

**Модель не знает, какой сегодня день.** В системную подсказку `core.chat`
подставляется текущая дата и время (`_now_line`), иначе на «какой сегодня день»
она выдумывает.

## Инфраструктура сервера

К коду не относится, но полезно знать: на этой машине развёрнута веб-панель
CloudCLI (Claude Code UI) за Caddy на `claude-work.duckdns.org`, служба
`cloudcli` на `127.0.0.1:3001`, ufw пропускает только 22/80/443.

**У панели есть HTTP API** — `POST /api/agent`, ключ в заголовке `X-API-Key`.
В `.env` он лежит как `CLI_CLAUDE` и с 11.09.2026 указывает на **вторую**
панель, не на корневую. Она запускает агента-кодера на проекте:
либо по `projectPath`, либо клонируя `githubUrl`, и умеет `createBranch` с
`createPR`. Это **будущий дом для самописных скиллов**, и подходит он именно
из-за PR: результат приезжает веткой на обзор, а не кодом, запущенным на ноуте
владельца. Для зрения API непригоден — поля для картинки в теле запроса нет
вовсе, да и класс задержки не тот.

**Вторая панель поднята и работает** (11.09.2026). Служба `cloudcli-jarvis` от
пользователя `jarvis`, порт 3002, хост `jarvis.claude-work.duckdns.org` (DuckDNS
раздаёт поддомены сам). Первая панель осталась под root вместе с проектами в
`/root` — это два уровня доверия, а не дубль: автономный агент живёт в песочнице,
которой `/root` недоступен по правам `700`.

**Из четырёх провайдеров нужен один, и он работает.** Решение владельца от
11.09.2026: на остальных забить. Для памяти, чем они кончились: `cursor` и
`opencode` — нет бинарников, `codex` доходит до OpenAI и получает 401 без ключа.

Грабли самой панели, на которые уже наступили:

- **Ключи API у каждой панели свои.** Ключ от корневой даёт на новой 401:
  хранилище в домашнем каталоге, а дома разные.
- **Мастер первичной настройки падает в чёрный экран** на шаге «подключить
  агентов». Причина в её собственном коде: сервер читает `DEFAULT` у каталога
  моделей, не проверив, что каталог есть, — а у непоставленных провайдеров его
  нет. Обошли отметкой в базе: `has_completed_onboarding=1` в
  `/home/jarvis/.cloudcli/auth.db`, копия базы рядом. Перезапуск не лечит:
  сервер тут ни при чём.
- **Нестримовый режим врёт**: возвращает HTTP 200, `success: true` и ноль
  токенов, хотя не запустилось ничего. Ошибку видно только при `stream: true`.
  Автоматика, читающая нестримовый ответ, будет считать провалы успехами.
- **Кириллица в теле запроса требует честного UTF-8.** Через параметр командной
  строки она портилась, и агент отвечал буквально «твоё сообщение пришло с битой
  кодировкой»; через файл в UTF-8 доезжает целой. Самого Jarvis это не коснётся —
  он ходит через `httpx`, — но диагностировать такое со стороны неприятно:
  ошибки нет, просто ответ не по делу.
- Провайдер `claude` под root не запускается вовсе: Claude Code отказывается
  работать с `--dangerously-skip-permissions` от root. Это и была причина
  завести вторую панель.

# Своя модель активации: «Джарвис» по звуку

Сейчас имя ловится по расшифровке: Whisper переводит фразу в текст, а Jarvis
смотрит, начата ли она с «Джарвис». Это работает и ничего не стоит, но у
способа есть потолок:

* **имя узнаётся только после конца фразы.** Пока Whisper считает, команда уже
  произнесена — приглушать музыку поздно, она записалась вместе с голосом;
* **в шуме Whisper ошибается именно на имени.** Оно короткое, редкое и стоит
  первым, то есть в самой невыгодной позиции. Отсюда весь список `aliases`
  в конфиге: «жаркость», «жарвиз», «дженнис».

Модель активации слушает поток кадрами и срабатывает через доли секунды после
самого слова. Готовой модели на «Джарвис» не существует — её делают под своё
имя, свой голос и свою комнату. Ниже — как.

Обучение идёт **на твоей машине**, не на сервере: там нет ни микрофона, ни
видеокарты, ни права гонять модели.

## Что получится на выходе

Один файл `jarvis.onnx` весом около мегабайта. Его кладут в `models/wakeword/`
и включают в конфиге:

```yaml
audio:
  wake_word:
    mode: acoustic
    model: models/wakeword/jarvis.onnx
    threshold: 0.5
```

Нет файла или не установлен пакет — Jarvis напишет предупреждение и продолжит
слушать имя по тексту. Сломать запуск это не может.

```bash
pip install -e ".[wakeword]"
```

## Как это устроено

openWakeWord не учит модель слышать звук с нуля. Внутри три ступени, и первые
две готовые:

1. **мел-спектрограмма** — превращает звук в картинку частот;
2. **эмбеддинг** — та же сеть, что стоит в распознавании речи Google: она
   переводит картинку в набор чисел, описывающих *речевые* признаки;
3. **классификатор** — маленькая сеть, которая по этим числам отвечает «да» или
   «нет». Учить нужно **только её**, и потому всё это влезает в час-другой на
   обычном процессоре.

Из этого следует главное: **обучающие примеры нужны тысячами, и записывать их
голосом не надо.** Их синтезируют.

## Путь первый: готовый ноутбук (проще)

У openWakeWord есть официальный ноутбук для Google Colab: бесплатная
видеокарта, всё уже настроено, на выходе — готовый `.onnx`.

1. Открой репозиторий проекта: <https://github.com/dscripka/openWakeWord> —
   в разделе «Training new models» лежит ссылка на ноутбук
   `automatic_model_training.ipynb`.
2. В первой ячейке впиши целевую фразу: `джарвис`. Русский там поддержан —
   синтез многоязычный.
3. Запусти все ячейки подряд. Займёт около часа, из них большая часть — генерация
   примеров.
4. Скачай получившийся `.onnx` и положи в `models/wakeword/jarvis.onnx`.

**Обязательно поменяй одно место.** В ячейке с настройками есть список фоновых
шумов для аугментации — по умолчанию там записи улицы и офиса. Твой фон другой:
музыка через колонку с сабом. Добавь туда свои файлы — десяток любимых треков в
WAV. Модель будет учиться слышать имя **поверх того, что у тебя реально
играет**, и это разница между «работает в тишине» и «работает у тебя».

## Путь второй: локально, у себя

Если не хочешь в облако — то же самое делается на ноутбуке. Дольше (несколько
часов на процессоре), но никуда ничего не уходит.

```bash
pip install openwakeword[training]
git clone https://github.com/dscripka/openWakeWord
cd openWakeWord
```

Шаги те же, что в ноутбуке, только руками:

1. **Сгенерировать произношения имени.** Нужны тысячи вариантов — разные
   голоса, темп, интонация. Инструмент — синтез (в примерах используется
   Piper, он у нас уже стоит с голосами `ru_RU-*`).
2. **Сгенерировать «не имя».** Случайная речь, похожие слова, тишина. Этого
   должно быть больше, чем самих имён: модель учится в основном **не**
   срабатывать.
3. **Подмешать фон.** Комната, вентилятор, и главное — **музыка**. Каждый
   пример смешивается с фоном на случайной громкости.
4. **Обучить классификатор** скриптом `train.py` из репозитория.
5. **Проверить на своих записях.** Наговори десяток «Джарвис» и десяток
   похожих слов, посмотри на пороги.

## Порог

`threshold` — цена ошибки в обе стороны:

* слишком низкий — ассистент откликается на постороннее слово в разговоре;
* слишком высокий — не откликается вовсе, и приходится звать дважды.

Начни с `0.5`, а дальше смотри в лог: при каждом срабатывании там пишется
уверенность («Услышал имя (0.87)»). Если ложных много — поднимай до 0.6–0.7.

## Что изменится в поведении

* **Музыка приглушается на слове «Джарвис»**, а не после команды. Ради этого всё
  и затевалось.
* **Текстовый гейт никуда не девается.** Он остаётся второй попыткой: модель
  промолчала, но Whisper услышал имя в расшифровке — команда всё равно
  выполнится. Две проверки лучше одной, а стоит вторая ноль.
* Имя из расшифровки по-прежнему вырезается, роутер получает чистую команду.

## Чего это не чинит

Модель узнаёт **имя**, а не команду. Саму команду по-прежнему разбирает Whisper,
и в шумной комнате он по-прежнему будет ошибаться в словах. Именно поэтому
приглушение звука — отдельная работа, и делается оно первым.

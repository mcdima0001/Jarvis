# Замер «где снято»

Отвечает на один вопрос и цифрой: **на сколько метров скилл `photo_place`
промахивается**.

Заведён 13.09.2026 и сразу окупился. До него скилл за сутки переделывался
четыре раза, каждая переделка проверялась на одной-двух фотографиях владельца, и
каждая давала уверенно неверный ответ. Первый же честный замер показал, где мы на
самом деле были: **ноль снимков из шестнадцати ближе пятисот метров**, девять без
ответа вовсе, медиана промаха семь километров.

Правило отсюда простое: **механизм, который нельзя измерить, не ставится.**

## Как прогнать

```bash
# набор уже собран и лежит рядом — 71 снимок, 32 города
python tools/photo_bench/run.py \
    --manifest tools/photo_bench/set.json \
    --photos bench/photos \
    --readings bench/said.json \
    --limit 20 --out bench/result.json
```

Снимки скачиваются при первом прогоне и кешируются в `--photos`. В репозиторий
они не кладутся: они не наши и весят много.

## Что печатается и почему два числа

* **Промах** — расстояние от ответа до настоящей точки съёмки.
* **Честность** — уложился ли промах в ту точность, которую скилл сам обещал
  вслух. «Москва, только до города» с промахом в три километра честно, а «с
  точностью до здания» с тем же промахом — нет, и вредно именно этим: такую
  ошибку не слышно.

## `--readings`: почему прочитанное кешируется

Замер распадается на две половины, и стоят они по-разному. **Чтение снимка стоит
денег** и от правок в коде не меняется: модель видит ту же картинку и отвечает то
же самое. **Поиск по карте бесплатен**, и правят как раз его — пороги, границы
области, правила согласия.

Без кеша каждая проба новой константы стоила бы полного круга запросов в облако,
а два прогона были бы несравнимы: модель отвечает не слово в слово.

## Откуда берётся истина

`collect.py` набирает снимки из Wikimedia Commons — те, у которых в EXIF есть
координаты **камеры**. Не объекта: у снимка горы с двадцати километров координата
объекта увела бы замер в никуда, а нам нужен ответ на вопрос «где я стоял».

Точки выбираются кольцом в 3–9 км от центра города, а не в центре: там обычные
улицы и дворы, а не достопримечательности, которые узнаются и так. Набор из одних
достопримечательностей хвалил бы скилл за то, чего он не умеет.

```bash
python tools/photo_bench/collect.py --per-city 4 --out bench/manifest.json
python tools/photo_bench/prepare.py --manifest bench/manifest.json --out bench/set.json
```

`prepare.py` разводит снимки по местам (серия с одной точки — это один замер, а
не четыре) и перемешивает города с постоянным зерном: прогон часто обрывают на
половине, и набор, отсортированный по городам, оборвался бы на Москве.

Грабли самого Commons, все стоили времени:

* **403 без опознавательного знака.** Нужен `User-Agent` в их формате: имя,
  ссылка, почта.
* **EXIF в выдаче API обрезан.** `iiprop=metadata` отдаёт полный набор только для
  одного файла за запрос. Качать ради него целые файлы не нужно: EXIF лежит в
  начале JPEG, хватает первых ста килобайт по заголовку `Range`.
* **Ссылка приходит с хвостом статистики** (`?utm_source=…`), и проверка
  расширения по концу строки отвергает все файлы подряд. Смотреть надо на путь.

Перед прогоном EXIF со снимка снимается — иначе скилл прочитает ответ вместо
работы, он смотрит в EXIF первым делом.

## Если замер выдаёт «не узнаю» подряд по всем снимкам

Первым делом проверить счёт, а не механизм. Ночью 13.09.2026 на это ушло
неоправданно много времени: OpenRouter отвечал 402 «можешь позволить себе 105
токенов из запрошенных 300», то есть деньги кончились.

```bash
curl -H "Authorization: Bearer $JARVIS_OPENROUTER_KEY" \
     https://openrouter.ai/api/v1/credits
```

Теперь такой отказ — отдельный вид ошибки (`LLMOutOfCredits`), и вслух он звучит
как «кончились деньги на OpenRouter, пополни счёт».
